# M5.12 experimental alpha candidate

`m5.12-rc.1` is a source-built Linux ARM64 laboratory candidate. Recommend a source
alpha for local demonstrations and controlled laboratories only. Optional Pi
installation and physical acceptance remain NO-GO; this is not a stable release.

- Add opt-in process/socket supervision with ordered short-lived private renewals,
  unpublished initial socket verification, and explicit operator guest attestation.
- Refuse delayed selected-text publication across revocation using an
  instance/revision epoch. Keep receipt, source-view and attachment fences.
- Demonstrate an original RT-11FB multiterminal application on a separately
  generated disposable monitor. This is not an RT-11 login-shell claim.
- Preserve genuine V7, BSD, RSX, Tektronix and original-device laboratories;
  report sustained operation separately from fixture and Pi measurements.
- Expand to 36 historical notes and retain 15 deterministic facts. The new frozen
  claim corpus recognizes only 2/12 cases; model explanations remain fallible.
- Exercise protected ARM64 upgrade, explicit rollback, failure recovery, mandatory
  memory refusal, uninstall and continued conventional V7 operation.

The Linux observer, modified Hacker Replicant app and sharing guard remain separate
lab tools, disabled unless explicitly configured and absent from this archive.
A surviving process/socket does not reveal its guest OS. Stop the actual bridge
and observer before intentional guest changes; independently verify and explicitly
approve the new attachment. Never identify a guest from its title or prompt.

**Rollback compatibility:** an older binary refuses the new supervision setting.
While stopped, restore the prior reviewed private configuration as well as the
older release. Never silently discard a required identity check to make a downgrade
start. Effective `MemoryMax=96M`, `MemorySwapMax=0`, HTTPS and private credentials
remain prerequisites; missing memory containment is a refusal.

No guest media, manuals, model weights or private evidence are distributed.
No GPIO, physical controls, emulator lifecycle or boot selections are changed.

Use the `source_revision` in COMPATIBILITY.json instead of `main` for the exact
candidate's documentation. Checksums detect changes; they are not signatures.
