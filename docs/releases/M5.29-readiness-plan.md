## Qualification gates and recommended sequence

1. **Pin the candidate scope.** Choose a new source commit after the focused docs
   corrections, with a clean tree and all accepted tags preserved. Explicitly
   separate source demo, controlled guest labs and unqualified physical use.
2. **Reconcile documentation and real images.** Update current entry points above,
   verify links and commands in disposable locations, capture only the necessary
   real views, and record remaining website access limitations.
3. **Repeat source-package qualification.** Review exact members and notices;
   exclude private evidence, credentials, transcripts, guest media, model weights,
   executable binaries and production configuration. Verify safe paths, manifests,
   deterministic size/hash/member identity, clean extraction, offline/source build,
   applicable tests and unchanged originals. Do not assume main's successful build
   proves a newly exported archive.
4. **Record unresolved limits explicitly.** Original ARM64 exit-139 incidents and
   the V7 plotting timeout remain unexplained; independent security/historical
   review is pending. Preserve guest-identity, experimental AI, TM11 memory,
   START/ownership fail-safe and physical hardware/memory-containment blockers.
   They prohibit production claims; a source-only experimental candidate can be
   considered with accurate disclosure. A fresh privacy, preservation or core-test
   failure blocks packaging/publication until addressed.
5. **Present an exact proposal to the owner.** Supply candidate commit, proposed
   new tag/title, source archive name/size/member count/SHA-256, checksums, final
   notes and remaining risks. Publication needs a new explicit authorization.
   Website changes and announcements remain separate decisions.

Do not require physical deployment, new live networking features or a broad new
feature milestone to qualify Source Alpha 3. Recommend M5.29 as a focused
publication-readiness pass, with an honest NO-GO if package or review safeguards
fail. M5.28 publishes development documentation/code only; it creates no release.
