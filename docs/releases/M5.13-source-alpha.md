# Experimental source alpha candidate

**Publication addendum — November 22, 2026:** this exact candidate was subsequently
approved and [published as M5.13 Source Alpha 1](M5.13-publication.md).
These preparation notes retain their original approval boundary; use the
[quick start](../getting-started/source-alpha.md) for the released download.

This candidate is for technically capable enthusiasts who want to explore the
local demonstration or reproduce controlled historical guest experiments. It is
not a supported Pi installation, a stable release, or independent security
certification. Publication of a release/tag remains subject to owner approval.

The simplest path needs Git, Node.js **22.18 or newer**, npm and a modern browser.
No Pi, guest media, model, Go service or container is needed. See
[the source-alpha quick start](../getting-started/source-alpha.md). The offline
reference desk and exact calculator work without AI.

## Qualified scope

- Local HTML5/SVG desktop with labeled simulated panel, terminals and peripherals.
- Controlled genuine V7, 2.11BSD and RSX terminal subsets on disposable media.
- RT-11FB programmed multiterminal application I/O; no independent command monitor.
- Retained genuine LP11/PC11 and V7 graphics evidence, with guest-driver limitations.
- Experimental bounded model assistance; source wording is never silently certified.
- Reproducible security and interoperability review material.

Read the [capability matrix](../capabilities.md) and
[limitations](../known-limitations.md) before treating a facility as genuine.
The optional service is separately built and requires explicit guest approval,
private credentials/TLS and enforceable memory containment. It never starts an
emulator. Physical switches, original launcher, Screen, SSH and serial access stay
independent. The physical Pi is untouched in M5.13.

## Corrections in this candidate

Private control directories must belong to the service account. A reproduced
wrong-owner case now fails before socket creation. Concurrent consent publications
with the same epoch have a one-winner regression test.

Generated model answers always carry a source-status statement. Substantial
marked quotations are withheld because the installed catalog contains project
paraphrases, not authenticated primary-source quotation spans. This conservative
policy can refuse legitimate quotations too. Unrecognized formatting still carries
the visible notice. It is not a semantic truth detector. The MOVB note now explicitly
distinguishes a byte written to memory from register sign extension.

RT-11's fresh reproduction explains the older MTTEST status mismatch: its second
status word expectation predates the installed DZ character-size setting. The
original diagnostic is unchanged and still does not receive a full-pass claim.

## Source archive and approval boundary

The source candidate contains committed source, tests, documentation, notices and
small fixtures. It excludes guest disks, private transcripts/configuration, model
weights, generated executables and dependency directories. Existing upstream
notices remain. A source checksum detects changed bytes; it is not a signature or
a replacement for reviewing the supplied source.

From a clean committed checkout in the **Mac or Linux developer shell**:

```sh
python3 packaging/source-alpha.py m5.13-source-alpha.1 /absolute/new/candidate
```

The helper makes a deterministic archive, external checksum and file inventory.
It records the exact commit in `SOURCE.json`; `SOURCE_SHA256SUMS` covers source
members and that identity file. Repeat into another fresh directory to compare
bytes on the same Python/zlib toolchain. Cross-toolchain compression identity is
not promised. Build outputs are deliberately absent; `npm ci` verifies locked
package integrity when you build locally.

Verify the external `SHA256SUMS` before extraction, inspect archive member names,
extract into a new directory, and verify `SOURCE_SHA256SUMS` there. Use
`shasum -a 256 -c` on the Mac or `sha256sum -c` on Linux. Never extract over an
existing installation or working guest directory.

The final [M5.13 report](../lab/M5.13.md) records the candidate identity, tests and
recommendation. No GitHub Release, public release tag or downloadable binary is
created by this procedure. An ordinary source commit is distinct from release
approval. Previous milestone tags and packages remain unchanged.

## Review and report

Start with the [security packet](../security/M5.13-review.md),
[interoperability packet](../technical/hacker-replicant-interoperability.md) and
[review checklist](M5.13-review-checklist.md). Reproduce without physical hardware.
Report ordinary bugs with the exact commit, host/browser, steps, expected/actual
behavior and whether the case used simulation, fixtures or a genuine guest.
Keep credentials and guest content private; use [SECURITY.md](../../SECURITY.md)
for exploitable issues. Do not attach disk images to reports.
