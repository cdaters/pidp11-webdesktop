# 0007: Completed device observations and optional companion requests

Accepted for the M5.9.1 development increment, November 21, 2026. This is an application architecture decision, not hardware deployment acceptance.

The existing service remains the sole authority for authentication, terminal attachment generations and keyboard leases. Add two small optional services inside the same executable: completed device observations and configured chat. Neither can start or control SIMH, attach media, issue monitor commands or operate the panel.

Completed LP11/PC11 exports use an administrator-supplied file allowlist. A private local approval supplies a checksum and simulator/guest identities after the producer has closed the output. Publication copies at most 64 KiB per device, with at most four devices. Browsers receive immutable, generation-specific observations; they cannot choose a filesystem path or publish a file. Failed replacement retires the previous observation. Restart starts offline. Simulator/guest labels are administrator attestations, not automatic process discovery. The current implementation deliberately chooses completed exports over live file following: rotation, truncation and delayed flush cannot silently change an existing observation.

Configured chat reuses the bounded Ollama/OpenAI-compatible clients. Private configuration selects endpoints and an explicit model allowlist. Browser inspection makes no provider request; discovery and chat need deliberate actions. One shared in-flight slot, request limits and cancellation bound the service. Terminal sharing copies only the selected, bounded text into a visible review field. The model has no executable tools.

The first command approval path admits only `pwd` plus Return, `ls` plus Return, or `ls /` plus Return. It is disabled in private configuration by default and additionally requires a window opt-in. The user chooses a suggestion, reviews exact escaped bytes, then approves once. The server binds a random 30-second proposal to the current endpoint object, viewer and keyboard epoch, consumes it before writing, and uses the existing bounded terminal input path. Disconnect, lease change, ordinary typing and endpoint replacement invalidate old authority. Delivery uncertainty is never retried. A delivered byte sequence is not proof of guest command success. These names are not universally harmless in every possible guest shell; the operator must verify the UNIX guest and context. No arbitrary model-produced command is admitted.

This preserves small deployment size and avoids a database, model runtime, generic plugin privilege or second transport architecture. The costs are explicit operator publication, no continuous spool tail, a deliberately small suggestion vocabulary, and manual guest identity verification. Production integration still requires the independent physical-operation and memory-containment gates.
