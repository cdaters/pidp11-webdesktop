## Reproduced findings and corrections

| Failure demonstrated before correction | Correction and regression |
|---|---|
| Revoking while a selection-publication identity check was blocked could allow that older publication to restore the text | A mutex-protected revision fences pending publications. The deterministic channel test forces this ordering. |
| A second authenticated companion page could replace the shared text before the first page's question, causing different text to be sent under the first page's consent | Every publication returns a random 128-bit receipt. The question must present that exact receipt, and readback must match it before model access. Repeated identical text also gets a new receipt. |
| An authenticated malformed chat with `messages:[null]` raised a JavaScript exception | Validate each element before reading its role. The route returns HTTP 400. |
| A late private follow request could reopen a peripheral file after the follower was closed | Closing is permanent; subsequent start/follow operations cannot reopen descriptors. |
| Truncating and regrowing a spool between polls, on the same inode and to a greater length, could be mistaken for an append | Before accepting more data, compare the previously retained bytes with the open file. A changed observed window retires the observation. |

Tests are adjacent to [replicant](../../internal/replicant/lifecycle_race_test.go), [peripheral observation](../../internal/peripheral/shutdown_test.go), [view membership](../../internal/terminalbridge/observation_test.go), and the [modified app](../../integrations/hacker-replicant/read-only.test.mjs). `npm run test:replicant` runs the three isolated route regressions without starting upstream or a model.

The adversarial/source review also revisited authentication, exact origins, role separation, certificate checks, keyboard epochs, input sequencing, cancellation, bounded queues, slow-viewer removal and private operator approvals. The existing Go race/security tests and browser fixtures were retained. This review was performed by the implementation author with deterministic counterexamples and source checks; **it is not independent expert security acceptance**. No known regression was excused by weakening the authorization boundary.

The retained-window check is bounded to 64 KiB per device. It does not continuously authenticate older discarded bytes, defeat malicious parent-directory changes, or prove correct producer attestations. Completion still requires an independently checked whole-file hash. Revocation prevents future access; it cannot recall text already delivered or bytes already downloaded.
