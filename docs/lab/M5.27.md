# M5.27 — Genuine local modem and serial integrity

M5.27 established a repeatable text-only modem session using the original V7
`/bin/cu`, original SIMH/REALCONS, DC11 line 3 and an independent local peer.
Both directions have independent file checksums. A small read-only equipment
window observes the separate modem process; it has no dialing or guest authority.
Physical Pi access and networking beyond isolated loopback did not occur.

This is engineering qualification of a narrow laboratory subset, not owner
acceptance, a release or production approval. Source Alpha 1/2 and accepted tags
remain unchanged. The starting engineering revision was
`6ec09cbd908e930dc2611820a4352914b1adbe4a`.

## What the installed V7 software actually does

The original 7,140-byte cu and an unchanged-source rebuild using the original
compiler with `cc -O -n -s /usr/src/cmd/cu.c -o /tmp/cun` are byte-identical.
Guest cmp returned 0; independent reads of both files from the stopped working
disk produced SHA-256
`6f9b1beaf5e9506b66c10e34f7944dd45a22be2e12d7ef146d69bb629f6d1ea4`.
The earlier rebuild without `-n` produced a different 7,116-byte executable;
that was a build-mode mismatch, not evidence of a different installed source.
Neither rebuilt copy replaced the installed historical program.

The matching source calls ioctl with command and descriptor reversed. The original
libc assembly expects `(descriptor, command, argument)`. A clearly identified
new disposable guest probe verified a correct TIOCGETP call succeeds, whereas
the reversed call fails with errno 9, bad file descriptor. The inspected mode-1
logic also sets RAW and then masks flags with `ECHO|CRMOD`, which would discard RAW
even if its ioctl argument order were corrected. We patched neither defect.

Original V7 stty uses descriptor **1**. Earlier input redirection onto tty03 did
not configure that line. The legitimate installed-tool workaround, entered through
cu's shell escape, was:

```text
~!stty 300 raw -echo > /dev/tty03; stty raw -echo
```

The first command configures the serial device through output redirection; the
second configures the independent console. Before it, tty03 reported canonical
input and echo; afterward it reported speed 300, raw, no echo. An independent
peer's `OK CR LF` was echoed as four bytes before the correction and ceased being
echoed afterward. Raw console input then delivered exact `AT CR`, without requiring
an extra LF. Cu's failed mode restoration requires explicit `stty -raw echo -nl`
with LF after `~.` exits to the shell.

The installed source accepts a short speed table; unsupported `-s 9600` falls
back to B300. This milestone consistently used supported 300. It does not prove
physical 300-baud timing: emulated polling, buffering and host sockets intervene.
Cu's reader masks bytes with `0177`; all-byte binary transparency is not claimed.
Its receive diversion strips one CR immediately before LF and uses a fixed-size
line buffer. Its failed mode ioctls also mean intended HUPCL/speed-zero behavior
cannot be assumed. Peer/socket loss does not guarantee parent cu exits or restores
the console; explicit escape and recovery were tested.

### Layer separation and feedback

| Layer | Observed or inspected behavior |
| --- | --- |
| Guest terminal driver | Canonical buffering, echo and CR/LF flags; corrected by legitimate stty on the right descriptor |
| Original cu | Broken mode ioctls, seven-bit mask, local escapes, send-file and receive-diversion transformations |
| Original DC11 implementation | Emulated dataset/control bits and polling; DCO configured 7B; not a physical UART measurement |
| SIMH TMXR | Raw `notelnet` TCP transport; host connection state is not a browser-measured carrier pin |
| Independent peer/modem | Explicit command echo, exact received/sent byte capture, fixed local destination |
| Browser | Read-only modem facts in M5.27; no browser input was needed for the genuine cu tests |

A bounded replay of the M5.26 personality reproduced the feedback. Initial received
hex `0a41540a` generated `0d0a4f4b0d0a` (OK). The guest echoed a response prefix
`0d0a4f4b0d`, which the old command parser treated as a command and answered ERROR;
`0a0d0a4552524f520d` continued the loop. The old parser's command boundary was
reconstructed from raw captured bytes, not introspected from its private buffer.
The capture stopped after the observed loop within its deadline. No arbitrary
string filter was added. Correct guest no-echo/raw configuration removes the cause.
The new personality defaults to echo off and explicitly tests ATE1 separately.

## Genuine transfer and termination results

The original cu sent a generated two-line guest file through `~<`; the independent
peer received exactly 46 bytes. Its SHA-256 and the stopped guest file both equal
`dea39e96dce8b13d6d4e832804b8f88bd0fc7019b9a1ad4629796eafb1f15180`.
The distinct peer return used cu diversion framing and CRLF. The first wire
message was 63 bytes; the second was 64 because the fresh destination filename
was one character longer. Both resulting guest files contain exactly 44 bytes,
LF-normalized, SHA-256
`18501d1f30fbb47c5e2bb0e4258119a6dc894c3e95fade34c9a981e2f2c4861f`.
Independent stopped-disk extraction verified both; displayed text alone was not
used as proof of file receipt.

Genuine AT/OK, ATE0, ATE1 echo, ATI, rejected arbitrary dialing, unknown command,
81-character command overflow/recovery, ATDLOCAL/CONNECT, guarded escape, ATH/OK,
repeated command after hangup and explicit second dial passed. Peer absent returned
NO CARRIER. The second connection delivered a distinct message and peer disconnect
returned NO CARRIER. Some immediate console IPC responses split the longer ATI
reply; the continuous console and raw trace retain the complete response. This
was asynchronous display, not an assumed complete response per request.

Killing the independent peer during a receive diversion produced a 35-byte partial
file containing the prefix followed by NO CARRIER text. It is explicitly a failed
transfer, not a successful shortened file. Killing the actual modem preserved
SIMH and the independent console. A fresh modem process had a different instance,
zero counters and detached status; explicit renewed approval was required before
repeating the genuine exchange. The final active runtime includes the reserved
startup subscriber fix. Later source changes add observation and a test injection
seam with the same fixed production dial; the recorded runtime hash is preserved
separately from the final build, not represented as identical.

The original console answered distinctive markers after peer loss, modem death
and final disconnect. V7 then synced three times and SIMH quit with exit 0.
No guest restart, original-image modification or simulator patch was needed.

## Implementation, lifecycle and regression coverage

The [modem contract](../technical/local-modem.md) specifies the bounded parser,
fixed destination, ownership, guarded escape, count semantics and observation API.
The independent `cmd/local-modem` is not included as an automatically started
service. The ordinary desktop remains usable without it.

| Case | Evidence and limit |
| --- | --- |
| No approval; restart | Host tests start detached; actual killed/restarted modem remained detached until explicit approval |
| Wrong line/controller/guest profile | NewRunner validation tests reject; this is metadata validation, not automatic guest identification |
| Wrong process proof, expiry, reused listener/generation | New actor tests plus existing terminalservice supervision and terminalbridge replacement tests; old proof cannot revive a retired endpoint |
| Early guest bytes | Regression sends AT before socket verification; no early response, then exact OK after approval |
| Conflicting/stale keyboard ownership | Existing lease/epoch tests retained; actor checks acquisition snapshot and retires on subsequent loss |
| Peer absent, EOF, SIGKILL | Actual guest NO CARRIER; no automatic redial |
| Modem SIGKILL | Actual console remains available; new process has fresh authority state |
| Slow peer | Deterministic nonreading net.Pipe reaches 250 ms write deadline; attachment retires |
| Partial peer write | Injected prefix failure counts two bytes once, retires and does not replay; not a genuine guest throughput test |
| Guest disconnect / queue bounds | Existing bridge lifecycle, slow-observer/credit tests; actor closes owned sockets and joins readers |
| Browser disconnect/replacement/stale observation | Three-engine fixtures verify read-only GETs, explicit observation and retirement; no modem-control request exists |
| Unknown/oversized commands, escape timing | Host state-machine tests and actual guest commands; ordinary +++ data is not automatically an escape |
| Failed/partial receive file | Actual guest partial file preserved and independently extracted, explicitly unqualified as a completed transfer |

The first actor regression exposed lost startup AT bytes: subscription began after
the bridge had already read them. Reserving a bounded subscriber before reading,
while withholding it until verification, fixed the actual race. A subsequent
acquisition-snapshot check avoids confusing older queued state with current
ownership. The first strengthened test used an incorrect status-field name and
failed to compile; it was corrected before passing. These failures remain in
private evidence rather than being replaced by a success-only record.

Verification completed: `go vet ./...`, uncached full `go test -race -count=1 ./...`,
TypeScript checking, 110 frontend unit tests, browser/standalone/embed builds,
and static Linux ARM64 builds of the modem and optional service. The combined
modem/communications/guest browser run passed 21 tests across Chromium, Firefox
and WebKit. These are intercepted browser fixtures, not a claim of three genuine
modem-in-guest browser sessions. Genuine M5.27 tests used the independent console;
M5.26's earlier genuine three-browser serial evidence remains separate.

An initial browser campaign had 11 passes and one trace-file ENOENT failure when
another campaign reused the same output directory; the separate guest campaign
passed nine. The combined fresh-output rerun passed all 21. The frontend build
retains its existing large-chunk warning; no dependency or framework was added.
The initial diagnostic C upload also failed because V7's canonical erase character
was `#`; changing only the disposable console erase setting allowed the explicit
helper to compile. The first local peer restart hit TIME_WAIT/bind refusal; the
failed attempt was preserved and a fresh retry succeeded after ownership inspection.

## Resource observations

The active ARM64 modem snapshot reported RSS 8,720 KiB, high-water RSS 8,920 KiB,
eight threads and no swap. An approximately two-second sample used 0.483% of one
CPU core while idle in command mode. These are short laboratory measurements,
not sustained-load or Raspberry Pi results. The shared lab cgroup, including SIMH,
was capped at 100,663,296 bytes with swap max 0 and no OOM events.

One return-message console observation took at most 1,096.621 ms including operator
IPC and polling. That is not modem processing latency, a browser latency percentile
or proof of baud timing. The two-second request deadline and 750 ms observer poll
are design bounds, not measured end-to-end percentiles. Keep the enforced 96 MiB,
zero-swap companion target and investigate aggregate two-process containment before
any deployment proposal. Private status replacement is bounded; use runtime storage
rather than a growing history. The parser, credit queues and transfer caps remain
hard limits even when a test would otherwise pass by increasing them.

## Ethernet preparation: actual retained 2.11BSD inventory

A separate fresh disposable copy of the retained 2.11BSD image was booted
single-user, with only loopback in its Linux namespace. It reported kernel
`2.11 BSD UNIX #11`, built September 9, 2019, from `sys/PIDP11`. The existing source
configuration has `INET YES`, `NETHER 1`, `NDE 1`, `NQE 0`, `NQT 0`, `NSL 0`.
Installed `/netnix`, rather than `/unix`, contains `_deattach`, `_deprobe`, `_deintr`,
`_ipintr` and `_tcp_input`. This is actual binary-symbol evidence for the DEUNA/
DELUA and TCP/IP components; it does not prove a live Ethernet attachment.
Read-only `netstat -i` showed only the down loopback interface.

The actual utilities include `/sbin/ifconfig`, `/sbin/route`, `/bin/ping`,
`/usr/ucb/netstat`, `/usr/ucb/telnet`, `/usr/ucb/rlogin`, `/usr/ucb/ftp` and the
installed cu/tip hard-linked pair. Initial checks in guessed older paths found
nothing; the later directory inventory established these paths. No ping, telnet,
FTP session or interface-up command was executed. `/etc/netstart` contains de0
configuration and a default-route addition. It was inspected, not executed.
Any future lab must explicitly avoid that default route and unrelated startup
services. The disposable guest synced and exited; original BSD media is unchanged.

The original source revision is
`26d20beda0c6b5a1d3a5cb3d7a4dd494e02bff75`. In
`src/02.3_simh/4.x+realcons/src/quickmake`, NETWORK_OPT supplies `-DUSE_NETWORK`,
`-DHAVE_PCAP_NETWORK`, `-DHAVE_TAP_NETWORK`, include paths and `-lpcap`; its next
line also adds SLIRP flags/sources. Setting the unrelated top-level USE_NETWORK
make variable alone is not enough. The accepted lab Dockerfile explicitly builds
with `NETWORK_OPT=` and retains the original executable hash
`f38167163e37dbb9578f33cc58f9740e3a6408829c4e357637b76835864c8237`.
Thus its absent Ethernet backend is expected, not a guest-driver failure.

Source controller choices are XQ (DEQNA/DELQA) and XU (DEUNA/DELUA). XU is the
best first candidate for this retained BSD kernel's measured driver inventory.
`sim_ether.c` includes libpcap headers for PCAP and uses `/dev/net/tun`, TUNSETIFF,
IFF_TAP and IFF_NO_PI for Linux TAP. A separate build would need compatible headers,
link dependencies and reviewed compiler options. No new Ethernet build was needed
for this inventory, and the accepted binary was not changed.

Proposed future environment: an exclusively owned network namespace, a private
TAP interface with fixed private addresses, no default route, no NAT, no host LAN
bridge, no production interface and no public listener. Configure interface
ownership in a narrowly scoped privileged setup step; Linux TAP creation generally
requires NET_ADMIN, while packet capture backends can require NET_RAW and backend-
specific permissions. Those are future setup requirements, not capabilities added
to this milestone's labs. Prefer running SIMH unprivileged against an already
prepared owned TAP, then verify actual permission needs rather than assuming them.
A private veth/PCAP arrangement is another candidate. Ordinary TCP loopback cannot
stand in for Ethernet frames; SLIRP's routing/NAT behavior is not the preferred
isolation design and must not be enabled inadvertently by quickmake defaults.

A future genuine test must inspect CSR/vector matching, guest driver attachment,
private addressing, routes, firewall/exposure, frame transport, guest receipt and
independent-console recovery before claiming TCP/IP. DECnet is a separate guest
stack/configuration question; this inventory provides no installed DECnet or guest
DECnet traffic qualification. Existing RSX possibilities remain research, not
permission to boot another guest or contact a public network.
