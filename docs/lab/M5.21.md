# M5.21 — Supervised equipment sessions

Completed on 2026-11-23 in disposable Mac-hosted ARM64 Linux. This milestone adds
bounded, independently supervised LP11/PC11 sessions and genuine repeated RSX jobs.
It also demonstrates original RT-11 printer/tape handlers through the conventional
console. This is development main, not a release, owner acceptance or production
installation. No physical Pi, SSH, GPIO, website, upstream source or AI service was
accessed. Source Alpha 1 and Alpha 2 remain unchanged.

## Delivered behavior

The independent Go supervisor renews approval for an operator-attested guest,
exact producer and named device/job generation. It checks process/executable identity
without controlling SIMH. Completion distinguishes returned utility, drained device,
closed/flushed file and byte-verified artifact. Owner/generation checks reject stale
requests; lost supervision expires independently without killing the guest.
The [design](../technical/equipment-sessions.md) specifies authority, bounds,
retention and limits. [Lab runbook](../../lab/m521-equipment/README.md) and sanitized
[results](../../lab/m521-equipment/results/) preserve the reproducible subset.

Equipment windows keep separate simulation, observation and completed-export modes.
They show job/device identity, reported reader progress, completion phase and retained
incomplete data. Stopped observations are labeled cached. An explicit read-only
reader catalog shows name, size, hash, format and provenance. Browser mounting is
still unavailable because automatic safe-state detection has not been established.

## RSX: two printers and two genuine tape copies

RSX-11M-PLUS V4.6 BL87 used installed LPDRV, PRDRV and PPDRV; fresh `DEV LP:`,
`DEV PR:` and `DEV PP:` reported Loaded. The utility was **PIP M2101 (ANSI)**.
The original 11/70 had 4 MiB, RQ0 working disk and a DZ11 application line at
17760030/vector 330. The independently started bridge was explicitly attached to
that line. These M5.21 utility commands were operated through the conventional
console; browser evidence concerns actual device observation and downloads, not
new browser keyboard qualification.

For each printer job, `PIP LP:=TI:` received three separate authored records followed
by Ctrl-Z. Record one was `M5.21 RSX PRINT JOB 1 RECORD 1 - ORIGINAL LPDRV AND PIP`.
Job two used its own job number, spool and generation. After PIP returned and task
inspection showed it inactive, the private operator paused the original simulator,
verified LPT CSR `000200` and decimal POS 172, detached LPT and continued the guest.
Each output was **172 bytes**: FF, then LF + record + CR for each record.

Each tape input had 16 NUL leader bytes, 800 CRLF records and SUB, **48,817 bytes**.
Record one was `M5.21 RSX TAPE JOB 1 RECORD 0001 - ORIGINAL PRDRV AND PPDRV`.
Readonly readers and fresh empty punch spools were attached independently, then
observation was approved and started at zero bytes **before** `PIP PP:=PR:`.
Both copies produced **49,141 bytes**: 170 NUL bytes + input after its 16-byte leader
+ 170 NUL bytes. This is the observed installed-driver/utility transformation for
these fixtures, not a universal binary-copy or tape-format rule.

### Live observation and buffering evidence

The first Chromium run observed zero before the command, then 8,192 and 16,384 bytes.
Its console-log timing was not conclusive proof of overlap: the harness appends a
read batch after a short wait. The original timing flag is retained privately but
is not treated as decisive evidence that the guest was still writing at that instant.

The second Firefox run also began at zero. For a clear bounded visibility test,
the independent operator changed original SIMH's decimal PTP `TIME` register from
100 to 10,000 while the guest/device was idle. This supported original register
controls service delay; neither driver nor source was rewritten. It was restored
to 100 after the later interruption test. These timings are not a performance claim.

The second run recorded actual command echo, host file length and browser offset
at each sample. At 206 ms both showed 4,096 bytes, at 417 ms 8,192, at 624 ms 16,384.
At 1,467 ms the browser had 40,960 and the growing host file had 45,056; PIP's return
had not yet been captured. A later sample showed the return. This establishes
incremental observation during actual output growth, independently of delayed log
append. [Samples](../../lab/m521-equipment/results/live-punch.json).

The host remained at 45,056 buffered bytes despite the returned utility. Completion
required separate ready/no-error PTP CSR `000200`, POS 49,141, PTR POS 48,817 and
actual EOF CSR `100000`, then independent device detach/flush. Only the exact
closed 49,141-byte file was approved complete. Reader EOF alone did not complete
the punch. Reader progress displayed during execution was the last operator report,
not continuous register sampling. No completion was inferred from inactivity.

## Real supervisor crash and replacement

After successful exports, the first punch file was preserved as `punch1-completed.bin`.
A third explicit job reused that slot with a fresh empty `punch1.bin`, fresh generation
and the first readonly reader. WebKit verified the old live generation returned 404
and observed the new job before its PIP command.

After actual output began, the private harness killed **only the verified Go
supervisor process**, not SIMH. Approval expired **4,862 ms** later. The browser
retained **45,056 incomplete bytes**, kept completed download disabled and still
retrieved the previous immutable completed artifact byte-exactly. A new supervisor
attempting completion without a new owned session failed with “no active owned
session.” No silent adoption or operation replay occurred.

The original RSX console still answered `DEV PR:` and the guest completed PIP
independently. The operator then safely drained and closed this third device output.
Its bytes matched the first fixture, but it was **not retroactively published as
completed within the expired generation**. [Crash evidence](../../lab/m521-equipment/results/crash.json).
Observer-service replacement, wrong owners, delayed stale requests, sequential reuse,
rejected replacement retention, truncation and slow-reader behavior also have fixture
coverage; they are not all additional genuine guest crash experiments.

## RT-11: genuine second-guest device subset

A fresh disposable **RT-11SJ (S) V05.03** copy used the original 11/70 and RL02 disk.
Installed HELP documented INSTALL, REMOVE and COPY. Initial `INSTALL LP:,PC:` failed
with `?KMON-F-No room`. In the idle disposable monitor, CT and DM were installed
but unused by this configuration. `REMOVE CT:,DM:` followed by `INSTALL LP:,PC:`
succeeded; DL remained resident and TT available. SHOW DEVICES then showed LP at
177514/vector 200, PC at 177550/vectors 070/074. This transient working-guest change
is not a recommendation to remove handlers from another running system.

`COPY/ASCII TT: LP:` accepted three authored lines and Ctrl-Z. After monitor return,
ready CSR `000200`, decimal POS 152 and safe close, the printer output was **152 bytes**:
FF, three LF-ended records and an additional LF, with CR absent. SHA-256:
`88fe152c0f4021459ee05a292b4982dcfb8ac909e1329a64a10491b577b7d04a`.

`COPY/ASCII PC: T521.TXT` read a fresh 113-byte disposable tape. `TYPE T521.TXT`
read back all three authored records. `COPY/ASCII T521.TXT PC:` produced **512 bytes**:
the 96 bytes of CRLF records followed by 416 zero bytes. The input NUL leader and
SUB were removed. Final ready PTP CSR `000200`/POS 512 and PTR POS 113/EOF CSR
`100000` preceded detach. Output SHA-256:
`de43d4f115425eddacdff8bdbc84e131eedb16c4438eecda3b839301abdfda0a`.
[RT-11 results](../../lab/m521-equipment/results/rt11.json).
