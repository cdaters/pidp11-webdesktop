# Browserless rollback and partial-upgrade recovery

This procedure describes the design and the **disposable laboratory operation actually tested**. It is not authorization or a ready-to-run production Pi script. No service names or installed paths have been inferred from the active Pi.

1. Stop accepting virtual grants. Request consumer revocation; wait for actual quiescence and neutral effective controls. If the consumer cannot acknowledge, label its state unknown. Use the independent operator monitor if responsive; otherwise an explicit operator decision to terminate/recover the emulator is needed. Guest data may require filesystem recovery after an abrupt stop.
2. Stop the optional Web Desktop and broker. Stop the optional consumer instance. Disable any optional automatic restart source before changing RPC routing. Do not start the physical server while a broker or obsolete consumer can reclaim program 99.
3. Restore the saved, checksum-verified original executable/configuration/startup selection. Keep original binaries alongside test binaries; do not overwrite the only working executable. For a partial upgrade, the original configuration is the recovery source of truth. No ownership/lease is persisted for recovery.
4. Remove only the optional consumer's stale Unix endpoint after verifying that process is stopped. Inspect RPC registration. With the competing fixture endpoints stopped, remove program 99/version 1's old mapping and register the original physical route for **both UDP and TCP**. Verify the mapping before connecting the original consumer. On a real system the original server owns this registration; reconcile its startup scripts first.
5. Reconnect the unchanged SIMH/REALCONS to the unchanged physical panel route. Start halted; check lamp communication and neutral momentaries, then explicitly operate physical HALT/ENABLE and CONT. Do not assume an already-held START is safe to release. Do not restore a remembered browser owner or automatically send RUN/CONT/START.
6. Confirm the conventional console is available without a browser or Go backend. Keep SSH/Screen/serial/guest network configuration independent. Physical POWER, OS selection and host shutdown behavior require a separate hardware acceptance test; never simulate those by invoking production scripts in this lab.

The automated M4.1 rollback stops the fenced SIMH and broker, removes the lab's old registration, maps both transports to stand-in port 39100, starts the **original unmodified SIMH binary**, verifies physical RUN/HALT and executes `examine pc` through its independent PTY. No browser, fence or broker remains in that path. The stand-in substitutes for GPIO only; this does not prove real panel wiring, startup scripts, physical key-switch actions or guest OS recovery.

An abrupt-process-loss test kills the broker, consumer and stand-in and rebuilds a disarmed baseline. It approximates lost volatile state, not a real power interruption, torn filesystem writes, SD-card failure, orderly shutdown scripts or recovery of writable guest images. No guest images are used.
