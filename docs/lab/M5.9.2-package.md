# M5.9.2 alpha-candidate preparation

This is an optional static Linux ARM64 development candidate with embedded browser assets. It contains no simulator distribution, guest media, model runtime, private configuration or laboratory captures. It is not a stable release or production deployment authorization.

The staged package passed isolated systemd startup, repeat-configuration refusal, all three actual-service browser approval/provider cases, detached restart/session revocation, missing-memory-controller refusal and nine short resource scenarios. The final candidate is built from reviewed committed source; its exact artifact and final lifecycle outcome are recorded below after verification.

Both [installation paths](../getting-started/installation-paths.md) remain: use an independently working PiDP-11, or validate Raspberry Pi OS Lite and Oscar's software first. No clean-card replay or physical deployment occurred. The service remains disabled by default, requires enforceable 96-MiB memory containment and starts with terminal/device authority detached. Live-device supervisor qualification and real-model acceptance are pending.

Use the [optional-service procedure](../getting-started/optional-service.md) for private TLS/authentication, explicit guest approval, upgrade/rollback and removal, subject to separate host authorization. New `device_followers` configuration is optional. An older release may reject new schema fields; same-schema rehearsal rollback does not prove arbitrary historical downgrade compatibility. Preserve a reviewed compatible private configuration separately.

Source publication supplies code and reproducible packaging scripts. Candidate archives are retained locally, not uploaded as a stable GitHub release. No autostart, guest boot/shutdown, physical panel or media authority is added.
