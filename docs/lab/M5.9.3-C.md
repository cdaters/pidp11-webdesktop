# M5.9.3 Phase C — historical tutor and interoperability

Development evidence, November 21, 2026 (Mac local date). Baseline: Phase B implementation `b0d9280`, documentation `ef9a057`. The physical Pi was not contacted. No original installation, GPIO, media, boot selection, service or accepted tag changed. This is development qualification, not a stable release or production integration.

## Implemented behavior

The reference catalog grew from 14 to **24 entries**: 22 focused notes and two explicit scope notices. Ten new original summaries cover interrupt vectors, registers/status, autodecrement, UNIBUS, V7 `ls`, shell redirection and `ed`, VT100 cursor positioning, VT52 protocol differences, and SIMH disk/tape families. [Source metadata and digests](../../lab/m593c/results/sources.json) identify reviewed handbook OCR, original V7 manual source via TUHS, the VT100 User Guide transcription, and SIMH's August 11, 2022 manual. Original manuals are not redistributed.

The chat response now includes bounded claim annotations. Nine exact atomic fact rules distinguish recognized support from contradictions **only when the exact installed note was actually supplied**. Other text remains unverified or receives a calculation, version-context or unobserved-state annotation. A copied source ID or altered passage cannot supply verification authority. Annotations and source passages remain visible together; generated prose never becomes HTML. There is no confidence percentage or model-based self-certification.

The question box accepts `/calc 16 oct 177776` and other explicitly typed fixed-width calculations. It returns **65534 / FFFE**, signed-word interpretation and set bits locally, including when a provider is configured. Calculations never enter model history, submit shared excerpts or send guest input. Widths 8/16/22, explicit radix, signed decimal words, AND/OR/XOR and logical shifts share the existing exact integer validation. Overflow and unsupported expressions are errors, not implicit truncation.

A separate authenticated read-only Hacker Replicant adapter now serves deliberately published selections through actual HTTP. Each excerpt carries an endpoint and generation, expires after 30 seconds and is revoked on identity mismatch or explicit unsharing. There is no terminal reader, Screen control, automatic refresh, guest attachment or keyboard write. `/keys` always refuses. CPU state and upstream Screen existence remain unknown.

## Model comparison and claim-review limits

The [held-out questions](../../lab/m593c/questions.json) were written before the model run. Fifteen prompts include false premises, addressing, MOVB, vectors, V7 commands, ambiguous versions, unseen machine state, arithmetic, terminal protocols, driver availability, missing coverage and adversarial pasted text. Each was asked raw, with a selected Phase B note, and with a selected Phase C note. These are **explicit-context comparisons**, not a measurement of automatic search accuracy.

All three modes receive the same historical PDP-11/system framing and question. Settings: installed `gemma4:12b`, native Ollama/MLX, thinking disabled, 4,096 context, at most 512 output tokens, 20-second request deadline; other sampling settings use runner defaults. One response per cell is not a statistical benchmark. Editorial judgments compare prose to the recorded expected checks and retained sources; they are not independent expert certification or scores generated by Gemma.

Phase C repaired important gaps about vectors, stack pointers, V7 sorting/redirection and VT52. It still misinterpreted `@(R2)+` and incorrectly described octal 200's sign bit in MOVB. Its final arithmetic answer was correct but contained a false intermediate “one less” statement. Phase B attached valid citations to wrong autodecrement/register explanations. Every emitted reference ID was valid; **that did not establish factual support**. Gemma remains experimental.

The deterministic [20-case adversarial corpus](../../lab/m593c/claim-cases.json) produced the expected states: four recognized support cases, six contradictions, seven unverified cases, and one each calculation/live-state/version flag. No false support or false contradiction occurred in that constructed corpus; correct negations and paraphrases deliberately remain unverified. These cases exercise the limited rules and must not be presented as general language-understanding accuracy.

More importantly, **none of the 45 actual answers matched a supported or contradicted atomic rule**. Their prose was too varied or compound. In C there were 54 unverified units, six calculation flags, two version flags and three unobserved-state flags. The checker did not catch the two factual errors as contradictions. It avoids certifying them, but is an annotation system with low recognition coverage, not an automatic historical fact checker. Wider entailment claims would be unjustified.

## Separate-network gateway acceptance

The [cross-host record](../../lab/m593c/results/cross-host.json) comes from two disposable Debian ARM64 containers with different hostnames, network namespaces and process namespaces. They share the Docker Linux kernel and Mac hardware; they are not independent physical machines. The model-host container serves the production Go TLS gateway on loopback. The client uses the desktop's actual Go provider adapter. An internal Docker network carries restricted SSH forwarding from client to gateway. A separate management network exposes only temporary SSH at Mac loopback; it is needed because the fully internal network refused the Mac's reverse forward.

The Mac's already-running inference API stayed on loopback. A pinned, task-owned SSH reverse forward carried it to model-host loopback. Independent disposable client/reverse keys had target restrictions; no owner SSH identity or physical Pi alias was used. The client validated the TLS certificate through its private CA file. No runner-management endpoint or guest capability exists in this path.

Passed: real authorized conversations before and after explicit restarts; missing/wrong token; wrong TLS identity/root; wrong SSH pin; model allowlist; refused management; actual tunnel termination; model-host restart; client restart; manual recovery; runner disappearance without fallback. A labeled slow runner fixture additionally demonstrated approximately **20.14-second timeout**, concurrent-request refusal and cancellation reaching the runner twice. The fixture reads the request body before waiting so HTTP disconnects can be detected; the initial fixture omitted that and failed the cancellation assertion. That failed record was retained and corrected before the successful rerun. Real conversations and deliberate timeout fixtures are distinct evidence.

The final fault-stage containers used approximately 14.75 MiB (gateway/SSH/fixture) and 74.43 MiB (client/upstream Node/shim). These are lab snapshots, not the production service footprint or inference memory. An earlier gateway-only run measured 6.09/3.22 MiB. All task-owned containers, networks and SSH forwards were removed after each run. No permanent Mac inference exposure remains.

## Hacker Replicant demonstration

Upstream was refreshed and pinned at `6f8a2aca7786736e01bdf5ba9b44bf66a7f19349`. Its source remained unchanged. The actual Node application ran only inside the disposable client environment with tools OFF, no emulator, no owner host mounts and no guest media. It completed a real Gemma chat through the authenticated gateway, with an empty action log. [The record](../../lab/m593c/results/cross-host.json) includes the response, which followed upstream's Dutch tutor instructions; it is protocol evidence rather than a separate historical-quality score.

Direct upstream use failed correctly at the gateway's 4,096-byte per-message bound: its tutor prompt is over 5 KiB. A **lab-only shim** splits only the bounded system prompt into UTF-8-safe messages; the production gateway still enforces 20 messages, 16 KiB context, fixed model, no tools/stream and no management. The shim also handles an upstream status mismatch: upstream treats `running:null` as stopped. The adapter keeps its truthful `running:null`; the shim supplies an unavailable-status response that reaches upstream's existing unknown-state path. This is documented translation, not unmodified end-to-end compatibility.

The adapter's real HTTP tests showed selected synthetic text, endpoint/generation, unknown status and refused keys. Go tests additionally cover missing consent, expiry, generation change, non-revival, revocation, authentication and browser-origin rejection. The synthetic text is **not genuine guest acceptance**. Upstream tools-disabled chat does not fetch `/screen` itself; the harness explicitly exercised the readback route. Selected-text wiring into an upstream UI remains future work.

Upstream's chat handler does not propagate browser disconnect cancellation into its model fetch. Our gateway/provider cancellation works, but a disconnected upstream browser can leave its already-started request running until the gateway deadline. The shim is not a supported application integration or production service. No collaboration, endorsement or maintainer contact is claimed.

## Browser, packaging and resources

The final full browser suite passed **108 cases** across all three engines. The new test also waits for provider configuration before typing; an intermediate run exposed a test timing race in which the provider transition cleared text typed too early. The real-model browser run passed in Chromium, Firefox and WebKit: explicit sharing, historical explanation, follow-up, visible annotations/passages, local calculation with **zero model submissions**, cancellation and zero guest WebSockets. All guest lines stayed detached. WebKit evidence is not native Safari evidence.

The first real-model run exposed a display bug: source rendering cleared the previously appended review. It was corrected with separate containers and a regression case. Accepted screenshots were preserved; [the new tutor capture](../screenshots/m593c-companion.png) and [exact-values capture](../screenshots/m593c-exact-values.png) show the real application with actual Gemma responses and a clearly labeled synthetic excerpt.

Go vet/race, strict TypeScript, 92 frontend units, the transport integration fixture, retrieval parity and provenance checks passed. The current catalog lookup benchmark on the Mac M4 Pro was approximately 195 microseconds, 39,864 allocated bytes and 361 allocations per call. No inference is involved in search. These are Mac measurements, not Pi claims.

A disposable, isolated Debian Trixie ARM64 VM used 1 GiB RAM, two CPUs and 4 GiB disk, with external networking down and no original emulator installed. The package stayed disabled by default. Restart changed instance identity, revoked the previous browser session and left every guest line detached. Removing memory-controller availability caused startup refusal **before HTTPS opened**; restoring it recovered normal protected startup. `MemoryMax=96M`, swap zero and the existing soft Go memory target were preserved. Early detached startup measured about 3.32 MiB in the service cgroup; it is not a sustained workload peak.

The model runner reported 16,374,442,052 bytes (about 15.25 GiB) allocated with 4,096 context in this run. That API allocation field is not an independently measured RSS peak. Inference belongs on the capable host, never the Pi 3B+. No new weights were downloaded. Exact candidate hashes, final lifecycle/rollback/removal and cleanup results are recorded in the publication addendum below.

## Remaining work

2. Add verified release-specific RT-11, RSX-11M-PLUS and RSTS/E source passages; expand ASR-33/VT220/VT11 coverage. Existing scope notices remain explicit.
3. Agree a status schema, authenticated selection transport, prompt limits and disconnect behavior before a supported Hacker Replicant integration. See the [specific upstream questions](../technical/hacker-replicant-interop.md).
4. Rehearse an optional owner-managed Linux/Mac model-host setup on truly separate physical hosts when authorized. Container namespace acceptance does not establish home-network administration or production reliability.
5. Keep physical repair and M5.8 deployment separate. No future hardware access follows automatically from this milestone.
