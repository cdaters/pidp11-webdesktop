# Proposed read-only pilot: decision and rollback

2026-11-17. **Not executed. No Pi contact, discovery, SSH, deployment, GPIO changes or startup changes occurred.** Golden microSD verification and acceptance of a local checkpoint do not authorize any production step.

## Decision

**NO-GO for installing/running a production pilot now.** The offline implementation is ready to inform a separately authorized **read-only inventory and compatibility audit**. A read-only browser does not make a consumer patch or launch change harmless. Installed binaries, source revision, launch scripts, users, physical daemon behavior, console routes, timing, certificates and rollback have not been inspected on the Pi. Remote control remains blocked independently of observation readiness.

## Proposed sequence after separate explicit authorization

1. Record the authorized host identity and exact task scope; verify the already-created golden backup and recovery access with the operator. Do not discover hosts or infer permission from backup completion.
2. Inventory installed source/binary hashes, services, effective users/groups, RPC registration, GPIO daemon, Screen/serial/SSH routes, guest disks and startup configuration using read-only methods approved for that audit. Record a physical-only baseline and normal operator recovery procedure. Do not issue extra side-effecting GET calls as a monitoring probe.
3. Reconcile the installed consumer with the pinned laboratory source. Decide whether a minimal optional passive publisher can be built separately without changing CPU/controller semantics. Preserve the official executable and original launcher. Reject mismatched or unknown ABI/hooks instead of replacing production files speculatively.
4. Prepare a versioned, root-owned companion directory and a dedicated unprivileged observer account, private runtime directory, explicit publisher PID/start identity and socket group. Prepare an operator-managed trusted TLS certificate, fixed origin and random observe-only credential. Review file permissions, certificate renewal and local revocation. The laboratory self-signed certificate generator is not a production PKI system.
5. In a separately authorized maintenance window, stage the optional consumer beside the official one, with a reversible, explicit launcher selection. Do not replace `/opt/pidp11`, enable a service, reboot, change networking, mount guest disks or auto-start the emulator merely to stage files. The actual installed service structure must determine the final reviewed commands.
6. Enable only observation under supervision, with one viewer first. Compare physical polling, effective controls, lamps, RPC registration and independent console access against baseline. Exercise receiver stop/crash, stalled browser, expired credential, publisher restart and socket loss. All must degrade observation without altering the original physical route.
7. Measure incremental RSS/PSS, CPU, traffic, freshness and guest throughput on the Pi itself, including thermals and throttling. Increase to two then eight viewers only within the agreed budget. Stop the pilot on unexplained state changes, routing differences, missed physical controls, memory growth or resource contention.
8. Stop and disable the pilot after the agreed observation period unless continued operation is explicitly authorized. Report evidence before any terminal, media or control work.

## Proposed rollback

Stop the observer first. Its disappearance must only remove visualization. Revoke its credential, remove its listener/firewall rule if one was separately installed, and preserve logs. If the optional publisher consumer needs replacement, use the existing operator-approved guest shutdown/stop procedure; do not kill a running guest merely to remove a UI. Select the untouched official executable/launcher, remove the optional publisher environment and private runtime socket, and verify the original physical-only path plus conventional console access. No broker routing should have been installed by a read-only pilot. If routing differs, stop and investigate rather than silently repairing registration while a guest runs.

Rollback is conditional on the actual installation and guest-safe lifecycle. The network-none lab demonstrates original-binary/physical-stand-in routing and independent terminal access; it does not prove recovery from SD corruption, real power loss, GPIO failure or a production service-account mismatch. Destructive media restoration is a separate operator decision, not an automatic fallback.
