### Corrections found while qualifying the tests

The first Linux run refused the missing explicit lab environment flag before
running tests. The corrected invocation then exposed a **test assumption**: UID 0
with only CHOWN lacks permission override inside another user's 0700 directory.
The production owner check refused correctly, but the old test interpreted its
subsequent `Lstat` access error as evidence that a socket was created.

The test now requires the intended owner-refusal error, restores ownership of only
its temporary directory, and verifies absence. It passes under the same restricted
capabilities. Production enforcement was not weakened or changed.

An initial expanded TLS command returned cached Go output. Because Go's cache
does not track the Node probe's transitive imports, qualification was repeated
with `-count=1`; the recorded output includes the new two-caller cases. Reviewer
commands now force execution. A cached prior result is not counted as testing the
changed probe. [Corrected attempts](../../lab/m516/results/corrected-attempts.json).

## ARM64 fault capture and bounded findings

The new recorder runs one owned child at a time and persists native `wait4` status,
exit code versus signal, executable hash/mode/size, kernel and mount metadata,
resource limits/events, lifecycle timestamps and bounded process snapshots.
Deadline intervention is identified explicitly, and only that child's new group
is signaled/reaped. No failed directory is automatically removed or retried.

Four synthetic controls in offline Linux established the distinctions:

| Deliberate control | Native wait status | Interpretation |
|---|---:|---|
| Python explicitly exits 139 | 35584 | Exit code 139; no signal |
| Owned Python child receives SIGSEGV | 11 | Signal 11; no normal exit code |
| Deadline expires | 9 | Parent's recorded SIGKILL intervention |
| Execute permission absent | 32256 | Wrapper exit 126, separately recorded pre-exec EACCES/errno 13 |

These are diagnostic fixtures, **not recurrence of the original Go failure**.
Core dumping was disabled; no core/backtrace is invented. Output files are bounded
at 1 MiB and snapshots at eight per case. Very short processes may exit before a
mapping sample, and a sample may precede exec; it is not automatically a Go runtime
map. [Native controls](../../lab/m516/results/native-status-controls.json).

The actual comparison used the same separate Debian **6.12.118+deb13-arm64** QEMU
kernel as M5.15, software-emulated Cortex-A72, two vCPUs and 768 MiB RAM, without a
network device. This is not new physical ARM hardware or another independently
qualified virtualization platform. The ext4 image was backed by native outer-Linux
storage; the 9p share used the Mac-backed work directory.

Only four normal provisions ran: original/current binary × native ext4/shared 9p,
one immediate copy/execution per pair. All returned native status 0, with matching
before/after hashes. One additional original provision under strace exited normally;
its parent wait status is explicitly the tracer's, while the private syscall log
records its child. The trace includes memory/process/file operations and raw write
arguments, not private file contents. No unbounded retry campaign occurred.
[ARM64 results](../../lab/m516/results/arm64-provisions.json).

The cgroup check refused an unbounded service before listening, accepted the exact
96 MiB/zero-swap boundary, started detached and stopped normally on SIGTERM. One
idle snapshot measured **12,804 KiB RSS / seven threads**, with zero OOM events.
This VM sample is not Pi CPU, latency or sustained-load qualification. The unchanged
systemd unit retains its mandatory guard and disabled-by-default installation;
M5.16 did not repeat the full systemd install/rollback campaign.
[Resource record](../../lab/m516/results/arm64-resource.json).

The original 139 records still lack native signal/core evidence. These results
qualify a better capture path, not a fix or proof of which subsystem caused them.
