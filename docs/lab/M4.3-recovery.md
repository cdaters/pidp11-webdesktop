# M4.3 RPC budgets and recovery evidence

2026-11-17. All experiments are Mac-hosted network-none Linux ARM64, without GPIO or guest images. Original source and accepted original/fenced/observed/bounded binaries are preserved. The new `/opt/budgeted/pdp11_realcons` is a **separate optional experiment**, built from a copy of the M4.1 fenced tree by `lab/budget/apply.py`. It is not used by the normal desktop or passive-observation primary soak.

## Implemented operation budgets

| Operation | Optional budget / contract | Interpretation |
|---|---|---|
| RPC discovery | Explicit IPv4 loopback UDP socket, PMAP GETPORT on port 111; max 200 ms call | No DNS, rpcbind netconfig fallback or implicit zero-port lookup; only literal 127.0.0.1 accepted |
| UDP handle establishment | Explicit returned port, same consumer thread | UDP has no connected-peer handshake; allocation/scheduling are not hard real-time bounded |
| Individual generated RPC | min(200 ms, remaining operation budget), retry 50 ms | Uses libtirpc CLSET_TIMEOUT before every call; original rpcgen/XDR schemas retained |
| Complete attach | 2,000 ms shared monotonic deadline | Discovery, panel/control enumeration and connect callbacks share remaining time; expired calls are not sent |
| Service cycle | 300 ms shared deadline | GET, controller callbacks including lamp-test parameters, SET and nested error cleanup share it |
| Standalone disconnect | 200 ms shared deadline | Nested disconnect inherits the active outer budget rather than adding another allowance |
| Cancellation | Cooperative deadline, not asynchronous abort | No concurrent destroy/free, unsafe thread cancellation or claim of rolling back an already sent command |
| Watchdog acknowledgment | Existing M4.1 socket/lease protocol, measured separately | A callback can hold the fence mutex while waiting; an acknowledgment must not be inferred from a browser lease |
| Broker reconnect | Existing 20 ms mediation loop with bounded calls and fault state | No automatic ownership, rearm, START, CONT or RUN |
| Consumer restart | Explicit laboratory supervisor action, fresh process generation | No automatic guest restart or resumption; stale generations remain rejected |
| Unknown/stalled process | No unconditional deadline | SIGSTOP, scheduling stalls, kernel faults and physical failures can prevent confirmation; report unknown |

`wd_rpc_begin/end` nest across wrappers, so cleanup cannot reset a deadline. The modified copy also propagates control-descriptor enumeration failure; original code ignored that return value. Original emulator/controller behavior is otherwise retained. The generated client calls a common budget wrapper; it does not replace simulation or XDR. No TCP recovery implementation is claimed for this optional UDP consumer. The original C oracle still tests the Go server over both UDP and TCP.

[Source investigation](../research/rpc-m43-budget.md) explains why `clnt_create_timed` does not provide an entire discovery deadline and why libtirpc's datagram abort operation is not cancellation. Timer precision, scheduler delay, XDR execution, mutex contention and process lifetime remain outside a hard real-time guarantee.

## Tests and findings

Raw records are retained under `docs/lab/m43/`. The budget fixture tests absent rpcbind, a silent port-111 black hole, normal attachment, the original M3 generated-C oracle and REALCONS semantics, lost GET replies plus broker crash, and an actual controller lamp-test parameter callback. After each recovery, a restarted broker remains unowned and the consumer disarmed; no resume command is issued.

The aggregate descriptor fixture delays each new response by 75 ms and suppresses retransmitted duplicate responses only in that fault mode. The initial version delayed duplicates too, causing an earlier per-call timeout rather than exercising the aggregate deadline. The corrected experiment exhausts the shared attach budget and rejects the partial schema at **2.014 s** in its recorded sample. REALCONS reports disconnected. Early failure is safe, but it is distinct from demonstrating exhaustion of a complete-operation budget; both observations are retained in the development findings.

The pinned PDP-11/70 controller does **not** reference the `LAMPTEST` input in its control service. Its `set realcons test` operator command starts the timer that actually calls `realcons_lamp_test`. The held-parameter experiment therefore uses that genuine callback with the CPU already stopped/armed, then kills the broker. It measures bounded acknowledgment and no restart, **not a running-CPU halt latency**. A browser lamp-test pulse and the authentic cream paddle are currently a presentation/mock capability; do not infer complete real-controller wiring from their appearance.

The original M4 delayed START-release counterexample remains mandatory. M4.1's consumer fencing, stale/duplicate tickets, dispatch boundary, committed DEP limitation, physical handoffs, browser loss, expiry, consumer stall, daemon/broker restart, watchdog and browserless rollback assertions are retained. A revoked lease means authorization revoked; it does not mean the guest CPU is halted. Already dispatched or completed commands cannot be retracted. Confirmed quiescence requires the consumer's acknowledgment; stale, missing or blocked acknowledgment is unknown.

## Regression fixture correction

Repeated combined M4.1 runs reached the independent DZ11 section but timed out receiving its TCP/Telnet banners. The standalone DZ11 fixture passed. Inspection and a disposable diagnostic build distinguished the earlier physical HALT from the later serial fixture; the latter needs a clean device/timer epoch after preceding RUN/HALT fault tests. `terminal_probe` now explicitly resets **only the RAM-only test machine** before installing its scanner program. The three-second socket deadline, two independent line assertions and independent SIGINT/PTY monitor check remain unchanged. The test also waits for actual ENABLE polls rather than relying on a fixed 100 ms sleep. This is fixture initialization, not a production recovery prescription or an emulator-source change. The precise upstream calibrated-timer interaction remains an investigation limit; no guest-state preservation claim is made for that reset.

A disposable diagnostic copy prints only at CPU stop conditions. It is not used for acceptance or performance. Original source hashes are checked in the full regression suite. Resetting or killing a real guest is **not** authorized and is not equivalent to a safe guest shutdown.

## Remaining blockers

No unconditional fail-safe stop has been proven. The optional budget implementation has one tested transport/profile and finite adversarial coverage, not a verified cancellation system. Physical POWER/LOCK scripts, actual GPIO timing, installed consumer revision, privileged monitor access, guest storage consistency, terminal authority, service supervision and production clock behavior remain unknown. Read-only observation does not depend on this broker or optional budget copy; production control remains blocked.
