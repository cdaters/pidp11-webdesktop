# M5.9.1 alpha-candidate preparation

This development candidate is optional, static Linux ARM64 software serving embedded browser assets. It contains no guest media, original simulator distribution, model runtime, credentials or private laboratory captures. It is not a stable release or physical Pi deployment approval.

The stage-two package passed two-version install, repeat-configuration refusal, protected systemd startup, actual-service fake-guest/provider browser checks, detached restart/session revocation, missing-memory-controller refusal and nine short transport scenarios. The final versioned archive is built only from reviewed committed source; its exact revision, checksum and lifecycle outcome are recorded below after verification.

Both setup paths remain: [existing working PiDP-11](../getting-started/installation-paths.md#path-a-you-already-have-a-working-pidp-11), or [original software first on Raspberry Pi OS Lite](../getting-started/installation-paths.md#path-b-start-with-raspberry-pi-os-lite). The reviewed Trixie guide has not been replayed on a fresh card here. Existing hardware and enforceable-memory gates remain unresolved for production deployment.

Use the normal [optional-service procedure](../getting-started/optional-service.md) for private TLS/authentication setup, explicit guest-line approval and removal, subject to separate hardware authorization. New provider and device configuration is optional. An older release may refuse unknown new configuration fields; preserve a compatible reviewed configuration when rolling back across schema versions. The rehearsal versions contain the same new schema and do not prove arbitrary downgrade compatibility.

Public repository publication supplies source and scripts, not an automatic binary installation or GitHub stable release. No autostart, boot selection, GPIO or guest lifecycle authority is added.
