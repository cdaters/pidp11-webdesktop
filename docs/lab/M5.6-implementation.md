# Optional Web Desktop package: implemented laboratory candidate

**M5.5.1, November 19, 2026. Mac and disposable Linux only. Not installed on the physical Pi.** The [M5.6 specification](M5.6-deployment-spec.md) remains the deployment acceptance contract. This report describes the implemented candidate and the owner-facing procedure; it does not authorize production installation.

M5.6 adds a first-run configuration helper, a no-network configuration check, full-package checksums and both terminal personalities. See the [short owner procedure](../getting-started/optional-service.md) and [M5.6 results](M5.6.md). The original M5.5.1 rehearsal below remains historical evidence.

## What now works

`cmd/webdesktop-service` serves embedded browser assets over HTTPS with all guest lines detached. It reuses the existing authentication and terminal bridge. It never starts SIMH, REALCONS, Screen or a panel daemon and has no GPIO/media/launcher operations. The separate `terminal-pilot` checkpoint retains its original supervised startup behavior.

The desktop lists detached, attaching, attached and unavailable lines. Opening, signing in or refreshing the list never connects a guest. A local operator approves a verified allowlisted endpoint using a private Unix control socket. The browser then chooses that specific attachment generation and connects read-only. Keyboard acquisition remains a separate explicit action. A stale browser choice cannot follow a new attachment on the same port. See [ADR 0005](../decisions/0005-detached-terminal-service.md).

The service supports one to four literal-loopback raw guest lines. It has no arbitrary-target browser dialer, monitor route, boot endpoint or automatic reconnect. TLS is required, with a currently valid certificate matching the configured browser hostname and exact Host/Origin checks. Private inputs are bounded regular files; symlinks, world-readable secrets and malformed configuration are rejected. Connection limits apply before authentication: 64 public sockets and eight local control sockets, in addition to existing terminal/session bounds.

## Reviewable package

Developer **Mac shell**, from the repository, with the existing Go/Node build tools:

```sh
sh packaging/build.sh /absolute/path/to/a-new-package-directory
```

The script refuses an existing output directory. It builds a static Linux ARM64 executable, embeds the compiled browser application, includes notices and a checksum manifest, and copies the small install/select-release/uninstall scripts. The Pi would need neither Node nor Docker. The package is a development candidate, not a signed stable release; verify its provenance and checksums before any authorized installation.

Installed layout:

| Path | Purpose |
|---|---|
| `/opt/pidp11-webdesktop/releases/<version>/` | Immutable executable, notices, unit and checksums |
| `/opt/pidp11-webdesktop/current` | Explicitly selected release symlink |
| `/etc/pidp11-webdesktop/` | Private configuration, certificate/key and two role credentials |
| `/run/pidp11-webdesktop/` | Private temporary control socket; no saved attachment approvals |
| `/etc/systemd/system/pidp11-webdesktop.service` | Supervision of this companion alone |

The dedicated `pidp11-webdesktop` identity has no login shell, home directory, GPIO/disk/admin group membership or emulator dependency. Installation leaves the unit stopped and disabled. The unit uses `Restart=no`, an empty capability set, filesystem/device protections, 64 tasks and a provisional 96 MiB control-group limit. That limit is a ceiling, not a replacement for the lower RSS targets.

## Proposed owner setup — do not execute on the Pi without separate approval

First settle the switch-selection issue and review a new deployment authorization. Identify a reserved **guest-only** serial line through the independently operated emulator. This package does not add that line, modify a profile or choose an OS. A plain SIMH/operator console is not an acceptable substitute.

1. **Linux administrator shell:** verify the reviewed package manifest, then install a new version. The helper stops at an active/enabled companion, an existing unmanaged destination/account, a changed checksum or an already existing release.

   ```sh
   sudo sh /reviewed/package/install.sh /reviewed/package m551-candidate
   ```

   Expected result: only companion paths/account/unit are created; the service remains stopped and disabled. The original installation is untouched.

2. Choose the intended browser hostname, explicit bind IP and unprivileged port. The hostname must resolve on the owner's network, and the certificate must match it. The following uses **loopback for an isolated rehearsal**, not a suggested private network address:

   ```sh
   sudo /opt/pidp11-webdesktop/current/webdesktop-service provision \
     -directory /etc/pidp11-webdesktop \
     -listen 127.0.0.1:8445 -origin https://127.0.0.1:8445 \
     -endpoint 127.0.0.1:40100
   sudo chown -R root:pidp11-webdesktop /etc/pidp11-webdesktop
   sudo chmod 0750 /etc/pidp11-webdesktop
   sudo chmod 0640 /etc/pidp11-webdesktop/*
   ```

   Provisioning creates a new directory only, with distinct observer/writer tokens and a one-year self-signed certificate. It prints the certificate fingerprint, never the tokens. It does not contact the endpoint. For later LAN use, replace listen/origin with explicitly reviewed values; this milestone changes no network/firewall/DNS configuration. Do not use a wildcard bind accidentally.

3. Review `config.json` privately. Give each approved line a meaningful label and unique ID. Keep endpoint kind `raw-guest-line` and address literal loopback. A label describes operator intent; it does not verify the current guest. Trust the exact certificate on the owner's browser machine after independently comparing its fingerprint, or supply a certificate from an already trusted issuer. Do not disable TLS verification globally. Certificate replacement/renewal uses private files and a stopped service.

4. Start only the companion and inspect its state:

   ```sh
   sudo systemctl start pidp11-webdesktop.service
   sudo /opt/pidp11-webdesktop/current/webdesktop-service status
   ```

   Expected: a new instance ID, revision zero, every line `detached`. Open the configured HTTPS origin, then **Guest terminal**. Read the appropriate token from its private file locally and enter it in the password field. Never place it in a URL, command argument, screenshot or public log. Observer credentials cannot acquire a keyboard. The simulated panel and peripherals remain identified as simulated.

5. Independently verify the current guest and reserved line, then obtain fresh `status`. Approve the chosen line with the exact instance and revision just displayed:

   ```sh
   sudo /opt/pidp11-webdesktop/current/webdesktop-service attach \
     -instance INSTANCE_FROM_STATUS -id guest-dc0 -revision REVISION_FROM_STATUS \
     -guest-and-line-verified
   ```

   A refused/failed attempt is not retried automatically; inspect the cause and status. In the browser choose **Refresh lines**, select the newly attached line and **Connect**. It opens read-only. Acquire the keyboard only when appropriate. A connection is not proof of login, OS identity or CPU state.

6. Before intentional guest switching, **stop the actual companion process** through `systemctl stop pidp11-webdesktop.service`. Closing a browser is insufficient. After the independently managed guest changes, restart detached, verify it and approve afresh. For an individual line, the local `detach` command takes the same instance/ID/revision fields and invalidates pending attachment attempts. It sends no guest shutdown command.

## Upgrade, rollback, disable and uninstall

These are **Linux administrator-shell** procedures for a separately authorized installation. Save private configuration backups outside public packages. Guest images are never part of a companion backup or rollback.

- **Upgrade:** detach/stop the companion, leave it disabled, verify a new package and run its installer with a new version. Existing releases are never overwritten. Configuration is retained. Manually start, verify detached state and approve any guest connection anew.
- **Rollback:** stop the companion, run `sudo sh /reviewed/package/select-release.sh PREVIOUS_VERSION`, restore the privately saved compatible configuration if its schema changed, and manually start detached. The helper verifies the old release's checksums and restores its unit. It does not select or restore a guest disk.
- **Disable:** `sudo systemctl disable --now pidp11-webdesktop.service`. Confirm the process/listener are gone; use the existing console independently. No emulator operation is implied.
- **Uninstall preserving private records:** after stop/disable, run `sudo sh /reviewed/package/uninstall.sh`. Managed releases/unit are removed; private configuration and the inactive account are retained for review. Unknown release files cause a refusal.
- **Complete companion removal:** while the managed installation still exists, use `uninstall.sh --purge-private-config-and-account` instead. This explicitly deletes the five known private configuration/credential files and the dedicated account/group. It refuses unknown private files, symlinks, other account groups, group members or live account processes. Save wanted private records first. There is no `userdel -r`, original-installation removal or guest-image cleanup.

If a step fails, retain the stopped state and inspect the specific error. Do not resolve a stale socket by deleting arbitrary runtime paths or kill unrelated processes. systemd normally removes this unit's runtime directory on stop. Manual operation must remove only a confirmed stale companion socket after verifying that no service instance owns it.

## Executed rehearsal and limits

The package was installed into a new isolated Debian 13 ARM64 environment on the Mac, with systemd 257. Its external interface was brought down after prerequisite installation. Initial checks exposed an OrbStack-wide systemd override that weakened unit isolation; a **lab-only unit-specific override reasserted the package's protection settings**, and the lifecycle test was repeated successfully. The public unit itself was not weakened. This remains a virtualized Linux rehearsal, not proof of every Raspberry Pi OS kernel/systemd behavior.

The final rehearsal exercised stopped/disabled install, private provisioning, actual HTTPS assets without a guest, authentication, wrong-origin rejection, explicit synthetic line attachment, EOF, same-port non-reconnection, restart/crash, old-cookie revocation and independent peer continuity. A separate **network-none Docker** lab used verified disposable V7 media and unchanged original SIMH for genuine three-engine browser/console tests. Upgrade, rollback and complete companion removal are recorded in the [milestone report](M5.5.1.md) and sanitized evidence.

Still open: physical switch diagnosis and overall coexistence acceptance; sustained Pi resource/thermal/emulator-impact measurements; trusted LAN certificate deployment; per-user/per-line credentials; authoritative guest lifecycle evidence; passive panel observation. The two role tokens are a bounded initial installation model, not finished multiuser administration. An unchanged live stream can conceal a same-process guest change; the mandatory stop/detach procedure remains essential. No production service, copilot, remote panel control or GPIO integration was deployed.
