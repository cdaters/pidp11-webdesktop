## 3. Boot by physical selection and prove conventional access first

The owner sets SR bits 0–3 and clears the others, leaves the key in normal operation and HALT in the normal ENABLE position. The coordinator then runs in the **Pi Linux shell**:

```sh
/opt/pidp11/bin/pdp11control.sh start
screen -r pidp11
```

Use no selection argument. `start 0000` would pin IDLED across launcher restarts instead of reading the physical switch register. If Screen is already attached, stop and coordinate; never forcibly detach another operator.

Expected: the original launcher reports `unix7-web-pilot`, exactly one original simulator and panel daemon run, and REALCONS connects normally. Verify the active profile and exclusive copied disk through the independent operator/process evidence, not a browser label. Then follow the preserved V7 boot prompts in the **guest console**: `boot`, `hp(0,0)unix`, Ctrl-D for multiuser mode, and the agreed guest login. Verify a harmless command and fresh echo output. Screen's detach sequence returns to the Pi shell without stopping the guest.

The owner confirms lamps and familiar selector behavior. A short HALT/CONT check can occur only at an agreed idle, synchronized point: pause using HALT, confirm the expected RUN change, return to ENABLE and operate CONT once. Do not press START, DEP, EXAM, POWER or a rotary encoder's restart action during an active guest. Record actual observations; do not infer hardware behavior from the simulated browser panel.

## 4. Attach the optional browser terminal once

In the **Pi Linux shell**, inspect `ss -ltnp` and `ss -tnp` again. Confirm port 40100 is bound only to loopback by the identified simulator, with its reserved line free. Check the current guest/profile independently. Do not eject another terminal or search for an alternate port. An immediate listener rebind can fail during TCP `TIME_WAIT`; wait for a deliberate operator recheck, not an automatic bridge retry or kernel-setting change.

Provision fresh observer/writer credentials and the exact TLS certificate using the existing [pilot provisioning boundary](../../lab/m53/README.md). Verify uploaded binary and configuration hashes, private regular-file permissions and certificate identity/lifetime. Start only the manually supervised bridge, using its reviewed absolute path and private files. An example **Pi Linux shell** invocation inside the new private directory is:

```sh
./bin/terminal-pilot-m55 \
  -config config/terminals.json \
  -token-file config/terminal.token \
  -observer-token-file config/observer.token \
  -tls-cert config/terminal-cert.pem \
  -tls-key config/terminal-key.pem
```

The exact candidate hash is in [M5.5 validation](m55/validation.json). It is not a globally installed command. In a separate **Mac shell**, after checking that local port 8445 is free, the approved SSH alias may be used for the tunnel:

Replace `APPROVED_PI_ALIAS` with the separately approved local SSH alias. That command was unexecuted at preparation time; the subsequently authorized tunnel and its verified shutdown are recorded in the physical-pilot report. Verify the provisioned certificate without globally disabling browser validation. Authenticate, connect read-only to the approved V7 line, then explicitly acquire the keyboard. Use `ls /` and a fresh echo challenge whose result is a distinct output line. Test an observer and a competing writer. The main browser panel remains simulated; keyboard ownership grants no physical-panel authority.

## 5. Verify independence, then switch guests while detached

Close/refresh the owning browser, reconnect with a fresh display, and verify read-only status before deliberate acquisition. Use the independent Screen console while browser windows are closed. Release clients and stop **only the identified bridge** with SIGTERM; confirm Screen and original panel operation continue. No emulator signal or normal-launcher stop command belongs to bridge cleanup. Bridge loss may hang up that guest login or its application; it must not halt the CPU.

Before any intentional guest reset, reboot, profile change or device reassignment, stop the bridge and verify its process/socket are absent. Browser “Disconnect” alone leaves the bridge's guest connection open and is insufficient. Keep the browser detached throughout guest switching.

Use the guest's clean shutdown procedure through Screen. For this V7 image the established sequence includes three `sync` commands, then an operator interrupt into the **SIMH monitor** and `quit`. Confirm `Goodbye`, normal Screen/launcher exit and original daemon cleanup. Do not use `pdp11control stop`, `pkill` or power removal as a substitute. If the console or guest state is uncertain, stop the procedure and retain evidence.

Now set all SR bits clear and start the original launcher again **without an argument**. Confirm its existing `0000` IDLED profile and original physical behavior with the bridge absent. This exercises physical selection without intentionally writing another original guest disk. Do not silently substitute an RT-11 boot: that would need its own media-change scope. Returning to V7 requires another normal operator-led transition and fresh guest/listener approval, bridge process, authentication, view and keyboard acquisition. A same-process reboot on a surviving connection remains invisible to the current bridge; unsupervised switching is not accepted.

## 6. Roll back and verify the original experience

1. Release/close browser clients and stop only the owned bridge/tunnel. Through the independent console, end the disposable guest safely if still running. Preserve its stopped working disk and logs; do not delete or overwrite guest work during rollback.
2. Confirm the installed selection map still has the exact approved proposed hash. If it changed independently, stop for reconciliation. Remove **only** `0017 → unix7-web-pilot` with the reviewed editor, preserving owner/mode. Verify the result exactly matches the saved original map hash and bytes. An old whole-file restore must never erase intervening owner edits.
3. Retire only the added profile after verifying no simulator has it open. Preserve its disk in the private pilot archive and remove the now-unused profile directory deliberately. Do not recursively delete the original systems tree or use a broad cleanup glob.
4. Remove temporary companion credentials and private key as agreed; retain the inactive candidate, certificate metadata, configuration and nonsecret evidence privately. No service was installed, so rollback must not disable unrelated services or RPC infrastructure.
5. Compare all original configuration/binary hashes and metadata, the original V7 disk's complete hash/mtime, and existing mapping entries. Confirm pilot listeners/processes are absent. Demonstrate normal physical-only IDLED selection and Screen access without the companion, then leave the machine in the owner's agreed state. Record any remaining original running process as intentional, not leaked pilot cleanup.

Acceptance also records a modest, separately agreed bridge/guest resource sample and health observations. Targets remain ≤24 MiB idle / ≤48 MiB active bridge RSS, <1% idle / <5% mean active single-core CPU, and <100 ms p95 added terminal transport latency. Short measurements cannot certify sustained power or thermal behavior. Stop at the agreed health threshold, lost independent access, unexpected physical behavior, guest/line identity mismatch or changed original files.

## Owner's physical-panel checklist

During the supervised test, the owner needs only to:

1. Confirm the existing physical machine and Screen access are working before changes.
2. When asked to select the pilot, assert SR bits **0, 1, 2, 3**, clear the remaining bits, and leave HALT at ENABLE. The coordinator starts the original launcher without a selection argument.
3. Observe lamps and selectors while the same V7 guest answers through Screen and the browser. Perform one agreed HALT/CONT pause/resume only when the coordinator says the guest is ready; avoid START, POWER, deposit/examine and rotary-push restart actions.
4. Report that lamps and normal controls still work after browser closure and bridge shutdown.
5. After confirmed guest-safe exit, clear all SR bits for IDLED and verify the original physical-only machine again.

The coordinator handles files, hashes, credentials, tunnel, guest commands and rollback. No owner action or approval is being presumed by publishing this plan.
