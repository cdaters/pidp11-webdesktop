# M5.0 Mac laboratory procedure

This procedure starts a disposable Research UNIX V7 guest with the original pinned SIMH/REALCONS binary, then connects actual browser terminals. It never uses the Pi, GPIO, private backup media or an installed Pi launcher. All commands below run in a **Mac shell** from the WebDesktop repository. The guest commands sent by the harness run inside disposable UNIX V7.

Prerequisites are the existing local OrbStack `orbstack` context, the pinned `pidp11-realcons-lab:local` image, Go, Node and installed project dependencies/Playwright engines. The tested versions are recorded in [the results](m50/validation.json). If the lab image is missing, `sh lab/build-image.sh` fetches pinned public source and builds it locally; stop on any failed checksum/build. Do not substitute an installed Pi binary or mount a working guest image.

## 1. Obtain and verify source media

Use the already retained public archive when available. To obtain a new copy, choose a new private directory and download the public archive on the Mac:

```sh
mkdir -m 700 .research/m50-download
curl -fL https://obsolescence.dev/pidp11/systems.tar.gz -o .research/m50-download/systems.tar.gz
```

The original acceptance used `.research/m50/media/systems.tar.gz`. The fresh-disk replay used that same verified archive. Downloading is the only guest-media step that requires public network access. Neither the archive nor a disk image is committed or included in a review package.

Prepare a **new, nonexistent** destination. This example assumes the retained archive and a fresh destination:

```sh
python3 lab/m50/prepare.py .research/m50/media/systems.tar.gz .research/m50-new
```

Expected result: `Verified read-only base and independent writable guest disk prepared.` The helper checks the full archive SHA-256, extracts only the expected regular disk member, checks its size and SHA-256, protects `disk0.base.hp` read-only, and makes a separate writable `disk0.hp`. It refuses to overwrite an existing destination. A failed verification is a stop point; do not boot the disk.

## 2. Start the isolated guest

In the first Mac shell:

```sh
export PIDP50_WORK=.research/m50-new
sh lab/m50/run.sh
```

Keep this process running. The helper builds embedded browser assets and two static ARM64 lab binaries, then starts a named disposable container with no external networking, no published ports, a read-only root, no Linux capabilities, a 512 MiB memory limit and a two-CPU limit. Only the designated lab directory is writable persistent media. A ready file prevents silently reusing a previously booted working directory through this helper.

Expected message: `Isolated UNIX V7 guest, independent operator/DC11 line, and terminal bridge ready`. The harness boots the copy, enters multiuser mode, logs into the public image's demonstration account, prepares the guest-emitted VT100 sequence file and connects an independent conventional DC11 line. It creates private short-lived access credentials and a test certificate. If boot, login, line attach or TLS startup fails, stop here and inspect the private launch log. Do not reset the guest or rewrite disks blindly.

The actual replay used `.research/m50-replay` and completed this helper successfully. The original pinned binary is `/opt/lab/pdp11_realcons`; the existing PTY initialization shim is lab infrastructure, not a change to SIMH source. No panel broker, REALCONS connection or rpcbind registration is needed for M5.0.

## 3. Forward the fixed laboratory service

In a second Mac shell:

```sh
python3 lab/m50/forward.py
```

The relay binds only `127.0.0.1:8445` on the Mac and forwards opaque TLS to port 8445 on the named container's loopback interface. It accepts no caller-supplied address and caps concurrent forwards at 32. It does not install anything or modify browser/OS trust settings. If the port is occupied, identify the existing local process instead of killing an unknown service.

The endpoint is `https://127.0.0.1:8445`. Automated tests use a private context that accepts this ephemeral test certificate. A manual browser may present a trust warning; do not install the lab certificate as a system trust root or disable browser security globally. The saved real-session screenshots allow review without changing personal browser settings.

For a manually trusted local test context, open **Guest terminal**, sign in using the owner-only `terminal.token` file from the selected private lab directory, select `UNIX V7 · DC11 tty00`, then **Connect** and **Acquire keyboard**. Do not share or paste the token into documentation, URLs or logs. `observer.token` permits viewing only. A connected line may already be logged in; Enter can reveal a prompt. Use the public fixture account `dmr` only when the guest actually shows `login:`. This is not a credential for any Pi or private account.

Choose **# · UNIX V7 erase** for Backspace when using the image's default `stty` settings. Type `ls /` and Return to list the actual guest root. To end browser participation, release the keyboard and disconnect; this does not shut down the guest.

## 4. Run the genuine demonstration and measurements

In a third Mac shell, with the same work directory:

```sh
export PIDP50_WORK=.research/m50-new
node lab/m50/browser.mjs
node lab/m50/measure.mjs
```

Run these sequentially: they share a private request/response channel with the harness. The first command exercises genuine logins and commands in all three browser engines, multiple observers, independent keyboard lines, explicit reconnect, original console access and a bridge stop/restart. It writes real screenshots and private acceptance results. The second records short bridge-only RSS/CPU samples and ten real command timings. Neither is a production Pi benchmark.

Expected final acceptance message begins `PASS: genuine guest commands`. Treat a failed assertion as a failed checkpoint. Preserve its private log and inspect the state before continuing. No test failure should be hidden by replacing real output with a fixture.

The ordinary regression commands are separate from genuine guest acceptance:

```sh
npm run check
npm test
npm run test:integration
go test -race ./...
```

For the complete Playwright desktop suite, start the usual loopback Vite development preview on port 5173 and the mock backend on port 8080, then run `npm run test:browser`. These tests include explicitly intercepted transport fixtures and mock peripherals. The genuine script above uses port 8445 instead and does not intercept transport. Prior DZ11 RAM-only transport regression can be run with a fresh results location:

```sh
PIDP11_RESULTS_DIR=.research/m50-terminal-regression-new sh lab/run.sh --terminal
```

Do not run the old long stress/fault campaigns merely to obtain screenshots. Their preserved records and safety limitations remain independently applicable.

## 5. Shut down through the independent operator

Close test browser contexts. In the third Mac shell:

```sh
python3 lab/m50/control.py shutdown
```

Expected output includes guest `sync` commands, the independent `sim>` monitor, `quit` and `Goodbye`. The first shell then exits and the disposable container is removed. Stop the Mac relay with Ctrl-C in its own shell. Verify the named container is absent:

```sh
docker --context orbstack ps --filter name=pidp11-m50
```

This is the tested disposable V7 cleanup. The browser has no shutdown API. If the helper times out, inspect the private harness log and identify the guest's actual state; do not claim a clean shutdown or automatically delete its working disk. Retain failed-run evidence.

Private working disks, tokens, ready files and raw logs remain in the ignored lab directory for inspection. They must stay outside public packages. The source archive/base hash can be rechecked independently; never use the writable guest copy as the next run's source. `prepare.py` provides a new copy for another run.
