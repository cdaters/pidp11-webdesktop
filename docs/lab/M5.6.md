# M5.6: terminal personalities and optional deployment preparation

**November 19, 2026. Local development and disposable ARM64 Linux, plus explicitly authorized read-only Pi inspection. No physical deployment, GPIO execution or guest interaction on the Pi.**

The optional service is closer to an ordinary installation: first-run configuration sets private permissions, a separate check validates files without opening connections, and complete-package checksums include the helpers. Guest terminals now offer VT100 and an initial VT52 text personality with the same connection/ownership safeguards. A separate bounded Tektronix 4010 SVG fixture demonstrates incremental graphics decoding. VT11 remains an architecture proposal.

This is **not physical-coexistence acceptance**. M5.5's all-DOWN selection discrepancy remains unresolved. Original PiDP-11 controls, console, launcher and media remain authoritative and independent.

### Failures found and corrected

The old guest harness assumed that 500 ms was enough for a login prompt. A first run sent an echo command while login was still arriving. The new harness waits for recognizable login/shell prompts, allowing renderer whitespace. Failed runs and disposable disks were retained privately, and the final six-case run used another fresh disk.

The genuine Firefox test then exposed a real UI defect: refreshing a directory whose map iteration order changed could replace the chosen line with another first row. The view now preserves its selection by endpoint ID. A three-engine regression explicitly reverses directory order; stale-generation rejection still works. An initial assertion used a select-only matcher on an option element; correcting that test assertion produced 18 passing final fixture cases. None of these failures was hidden by substituting a mock guest.

The final lab shutdown stopped the actual bridge first, issued three guest syncs, interrupted only the lab-owned simulator and quit. The verified base disk hash remains `fc04dab1e7f2fbf3ea4b44603ed2c9d6ba15f4f86c702d4a27a1dac725966f39`; modified disposable disks and private transcripts were retained. The named network-none container exited, the local forwarding/preview processes stopped, the optional service was completely uninstalled, and the known lab override and disposable systemd machine were removed. Unrelated containers were left alone.

Remaining gates are explicit:

1. Supervised physical switch diagnosis: no cause is established, and uncooperative GPIO startup cannot be excluded atomically by the wrapper. Do not sample unless the owner establishes exclusive maintenance.
2. Guest identity: EOF/generation fencing prevents automatic reuse, but a different guest on the same surviving stream can remain invisible. Stop the actual service before intentional switching; independently verify and approve afresh.
3. Physical deployment: certificate/network review, actual systemd isolation, representative Pi performance and complete supervised rollback still require separate authorization. The read-only audit grants none of these.
4. Historical terminals/graphics: qualify full-screen programs; add VT52 graphics/other documented gaps deliberately; test genuine 4010 application output before connecting it; discuss a separate VT11 observation hook upstream before implementation.

Original physical-only operation remains the non-negotiable fallback. No new physical-acceptance tag was created.
