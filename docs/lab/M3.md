# M3 — isolated original REALCONS integration

The Mac's existing OrbStack Linux ARM64 runtime hosts a disposable Debian laboratory. Run `sh lab/build-image.sh`, then `sh lab/run.sh`. This is development infrastructure, not the deployment architecture. The desktop remains a small native Go executable. Checkpoints `checkpoint/m0` and `checkpoint/m02` are preserved.

The runtime container uses `--network none`, no published ports, a read-only root, bounded tmpfs, 512 MiB memory, two CPU quota and 128 PIDs. It mounts only the test scripts/binary read-only and its own results directory writable. It receives no host socket, home directory, physical device, GPIO or Pi endpoint. Only loopback exists; the lab executable checks that condition before opening listeners. SETUID/SETGID permit rpcbind to drop privileges; KILL permits cleanup of that child. No SYS_ADMIN, NET_ADMIN or privileged container is used. Docker's [none driver](https://docs.docker.com/engine/network/drivers/none/) provides the network boundary.

## Original source and necessary portability adaptation

The public PiDP source is pinned to `26d20beda0c6b5a1d3a5cb3d7a4dd494e02bff75`; archive SHA-256 is `3f857439ec9ab63de1f227dc7779c5c69df99d050f90e52209359330a6d9c070`. The build script verifies it. The Debian base digest is pinned in `lab/Dockerfile`. Build packages are installed from Debian repositories; package versions should be recorded for each run, and full package/archive reproducibility is not claimed.

The upstream C sources, generated RPC stubs and REALCONS control logic are unchanged. The original quickmake is used with command-line networking/display/link options for a headless build. No installer, GPIO server, guest OS or disk image is run. A tiny test program in emulated RAM is sufficient to verify execution.

Unmodified execution initially failed to apply console commands because the original `scp.c` calls `ioctl(TIOCSTI)` to inject REALCONS-generated command bytes into its terminal. The current Linux kernel blocks that ioctl. The test-only `lab/ptyshim.c` intercepts that one operation and writes the identical bytes to an inherited PTY master. Other ioctls pass through. This preserves the original controller, command generation, SIMH parser and CPU implementation. It is a portability shim, not proof that this exact upstream build runs without adaptation on every Linux kernel. Host kernel settings and security protections were not changed. The shim is never linked into or deployed with the Go application.

## Implemented RPC boundary

`internal/labrpc` provides loopback UDP/TCP ONC RPC, bounded record fragmentation, deadlines, protocol-level failure replies, descriptor discovery and parameter/value operations. `Panel` reproduces the 29-descriptor order and widths of the original PiDP PDP-11/70 schema. The original generated C client/XDR implementation is compiled with a small assertion driver and tested over both transports through actual rpcbind registration, program 99/version 1. Unmodified REALCONS itself uses UDP; TCP interoperability is established by the original generated C client, not by changing REALCONS to TCP.

An optional exclusive-consumer gate is available for the broker. UDP duplicate requests return cached responses without advancing input consumption; the same peer/XID with a different request is rejected. Cache size and lifetime are bounded (4,096 entries, 35 seconds); capacity exhaustion returns an RPC error instead of evicting live entries and replaying mutations. This is not persistent exactly-once delivery. AUTH_NONE only is supported. The transport is an isolated fixture, not an authenticated production RPC service.

## Actual findings

- Original C: UDP and TCP discovery, all 29 descriptors, input reads, lamp writes containing high bytes, end-of-enumeration errors, wrong output length rejection, and panel mode round trips passed.
- rpcbind advertised program 99/version 1 over both UDP and TCP on port 39099. The Go server refuses to overwrite another port's existing registration. Registration lifecycle and collision behavior receive further M4 tests.
- Actual REALCONS: LOAD ADRS → DEP → EXAM deposited/read octal `12345` at `1000`, confirmed independently through SIMH's `examine` command and DATA output.
- START with HALT reset the CPU and set PC to the loaded address. CONT with HALT executed one instruction; PC advanced from `2000` to `2002`. ENABLE alone did not run. CONT with ENABLE ran. HALT stopped the loop. START with ENABLE remained stopped on assertion and ran on release.
- All eight address and four data selector values were exercised. Virtual address selections clear high address bits; CONS PHY retains the loaded physical address. BUS REG shows low SR bits while stopped, DISPLAY REGISTER was zero in the reset fixture, and mapping lamps reflected the actual MMU-disabled 16-bit state.

Evidence (transcript line endings/trailing whitespace normalized for Git): `m3-simh.log`, `m3-state.json`, the executable assertions in `lab/integration.py`, and transport tests in `internal/labrpc/server_test.go`. These tests are finite conformance evidence, not exhaustive hardware/OS validation. Java runtime interoperability remains deferred. No Raspberry Pi was contacted; backup completion does not authorize production integration.
