# M5.12 — supervised identity and experimental alpha qualification

M5.12 starts from published M5.11 commit `05b3dc67f9742a52c9d0b06f79ba2b26f305d773`.
All work used the Mac and owned disposable ARM64 Linux environments. No Pi, SSH,
GPIO, production disk, website or maintainer contact was involved. Original SIMH
source and executable remained unchanged. Accepted tags and the M5.10 README and
gallery are preserved.

The implementation adds ordered, expiring process/socket supervision and fixes a
reproduced sharing race. It also establishes a genuine RT-11 application terminal.
It does **not** establish authoritative OS identity or physical acceptance.

## Decision and supported audience

## A. Process, endpoint and attachment supervision

[`supervised_endpoints`](../technical/supervised-guest-identity.md) is optional
configuration over the existing terminal allowlist. Named lines require explicit
process, endpoint and operator-epoch assertions, followed by ordered private
renewals. The first socket verification gets a three-second unpublished window;
active authority expires after one second without renewal. Expiry closes only the
companion's guest socket and retires its viewers and keyboard leases. It never
starts, signals or stops SIMH.

The separate Linux laboratory observer uses a real pidfd, process start identity,
boot/namespace identities, executable inode, listener inode and the accepted
connection descriptor owned by the approved process. It checks its private Unix
socket identity and rejects ambiguity. It is not included in the service package.
The Go manager trusts that local observer's assertions; the operator epoch is
explicitly **attested**, not a measured guest OS identity.

| Scenario | Evidence and limit |
| --- | --- |
| Real supervised V7 | Original SIMH, browser input/output, observer renewal and protected ARM64 service passed |
| Same-name replacement / PID reuse | Linux child exit and replacement refused by pinned old pidfd; redirected `/proc` pathname models PID reuse; actual kernel PID recycling was not forced |
| Listener/endpoint replacement | Real Linux socket replacement and unrelated-owner refusal tested |
| Executable replacement in a live process | Real exec to a different executable refused |
| Browser refresh, observers and keyboard handoffs | Genuine V7/BSD and three-engine fixtures; no implicit keyboard reacquisition |
| Stale approval / concurrent approvals / reordered renewal | Go race tests; revision, instance and sequence fences; one concurrent renewal wins |
| Observer stall / partial loss | Actual ARM64 observer stopped with SIGSTOP; line became unavailable, proof removed; resumed observer could not revive it |
| Bridge forced termination / restart | Actual SIGKILL; no automatic restart; explicit start produced a new instance with detached lines; original SIMH continued |
| Stale Unix socket | Observer checks its original socket device/inode; service-instance fence independently refuses replacement; no claim of atomic filesystem observation |
| Guest switch in unchanged process and stream | **Not detectable.** Stop the actual observer/bridge first; independently verify and explicitly approve a new epoch |

The initial real-SIMH observer failed closed while waiting for SIMH's accept poll.
The bounded unpublished verification window corrects this without granting early
browser access or extending the active lease. A failed constructor's pidfd is now
closed; a Linux descriptor-count test verifies that refusal does not leak it.
An early VM fault harness expected `detached` after expiry; actual documented state
is `unavailable`. The assertion was corrected after recording the returned status.

Host scheduling, same-executable exec, descriptor inheritance, observations racing
with mutation and a compromised trusted local observer remain limitations. This
is a bounded supervised laboratory subset, not general production identity proof.
The original console and independent serial connection remain outside it. Host-wide crashes, actual kernel
PID recycling and forced browser-engine process death were not newly qualified.
After the completed V7 workload, stopping the real observer retired authority;
both conventional routes still answered. The serial response exceeded an early
0.7-second harness read and arrived on a subsequent read without replaying the
command. A device-producer setup attempted before the replacement service was
ready refused its private connection; its empty output files were preserved before
a fresh attempt. These setup failures are not device-phase passes.

## B. RT-11: a genuine additional application terminal

The immutable baseline still boots RT-11SJ (S) V05.03 without multiterminal support.
The supplied disk also contains FB/XM monitors, SYSGEN, monitor sources and the
original MTTEST program. The installed SYSGEN identifies itself as V05.52 (1986),
while the resulting monitor reports V05.03. This is a mixed supplied image, not a
newly authenticated complete V5.3 distribution kit.

A significant research correction: RT-11's `DZ.SYS`/`DZ.MAC` refers to the
Professional-series RX50 diskette device in the examined guide. Its installed
status cannot establish DZ11 serial support. The earlier M5.11 report is preserved;
the current capability matrix no longer repeats that implication.

The July 1984 System Generation Guide permits multiterminal programmed I/O in SJ,
FB and XM, using DL11/DZ11 lines. It does not automatically provide login shells,
and the described configuration excludes VT11/VS60 support. This guide is explicitly
earlier than V5.3. Actual installed help, source generation and running behavior
supply the image-specific evidence. [Source record](../../lab/m512/results/sources.json).

On the disposable working disk only, the test:

1. Invoked `IND SYSGEN`, selected FB, system-job and multiterminal support, one
   console DL line, one DZ11 multiplexer and one local DZ line at CSR `160100`,
   vector `300`, 9600 baud. Source, object and map devices were the working `SY:`.
2. Built the generated `M512C.MON` and `M512C.DEV` command files with the original
   guest assembler/linker. Kept generated masters and a backup of the working
   disk's prior DL handler. Installed a separate `M512FB.SYS` and its matching
   generated DL handler on that working disk.
3. Used original SIMH with DLI disabled and DZ11 enabled at the matching address
   and vector. `BOOT M512FB` reported RT-11FB (S) V05.03; `SHOW CONFIG` explicitly
   reported multiterminal support.
4. Assembled the supplied MTTEST using the generated conditionals. It attached
   console LUN 0 and additional LUN 1. Its console remained independently usable.
5. Connected Chromium through the normal Go bridge to the DZ line. The original
   application prompted for input, read `M512 BROWSER LINE` and printed it back,
   distinct from terminal echo. Disconnect/reconnect returned read-only.
6. Ended the application through its documented console control-C checkpoints,
   stopped the actual bridge, verified console `SHOW CONFIG`, and quit SIMH at an
   idle monitor prompt. Working media and raw transcripts were retained privately.

[Browser result](../../lab/m512/results/rt11-browser.json). Acceptance: boot YES;
console YES; separate serial application YES; browser YES; interactive application
YES; read-only reconnect and bridge-independent console YES. Independent login
shell NO; complete recovery campaign and full MTTEST diagnostic acceptance NO.
The older V3 MTTEST reported a LUN 1 terminal-status mismatch. Its input/output
exercise passed; that does not make the entire diagnostic pass.

Recorded failed attempts include invoking SYSGEN through `@` instead of `IND`,
using old answer files that prohibit changing multiterminal selection, an early
prompt parser reading a stale transcript, and booting the new monitor before its
matching DL handler (`Conflicting SYSGEN options`). Each was retained and corrected
at its actual boundary. No original media or existing accepted monitor was replaced.

## C. RSTS/E: exact remaining blocker

Original RSTS/E V7.0-07 booted, accepted the distribution account login and evaluated
BASIC `PRINT 6*7` as 42 through the original console. INIT hardware inventory saw
the configured DZ11 at CSR `160100`, vector `300`; `SET LIST KB:` listed only the
console TT and four pseudo-keyboards. The supplied `CONFIG.MAC` independently
showed `DZ11=0` (also no DH11/DJ11), consistent with that live inventory.

A raw connection to the simulator's DZ listener succeeded, but a carriage return
produced zero guest bytes during the bounded three-second probe. This is **not**
serial/login or browser acceptance. The V7 manual says omitted generated terminal
lines require regeneration; INIT SET cannot supply absent driver code.

The image contains SYSGEN/SYSBAT and a historical CREATE log, but searches of both
supplied disks found no CREATE.SAV or complete monitor build source set. A historic
log is not proof those inputs still exist. No new guest distribution was downloaded.
The technical blocker is the generated terminal configuration and incomplete
available regeneration inputs, not a missing browser feature. RSTS was shut down
through its own SHUTUP procedure and SIMH exited; immutable bases were preserved.

## D. Genuine regressions and sustained operation

V7 endurance and BSD endurance summaries are recorded in
[the result directory](../../lab/m512/results/). They measure Mac-hosted ARM64 Linux,
not a Pi 3B+. Container memory limits cover SIMH plus the companion and observer;
the separately tested systemd limit covers only the companion.

The completed V7 session ran **1,812.997 seconds** (30 minutes 13 seconds),
with 121 confirmed commands, 24 keyboard handoffs, ten observer replacements
and three explicit sign-ins. Sampled companion RSS was 10,676–14,768 KiB;
descriptors were 11–15 and goroutines 14–19, including a third passive observer.
Bridge CPU averaged 0.525% of one core; allocation totaled 315,266,016 bytes over
141 collections, with final heap below its initial sample. Echo round trips were
361–884 ms, including original SIMH polling, relay and browser. The whole 96 MiB
container reached 53 `memory.max` pressure events but **zero OOM/kills**; sampled
charge ranged from 71,266,304 to 98,832,384 bytes. This is a tight whole-lab budget,
not proof that the service alone needs 96 MiB. No persistent descriptor/goroutine
growth was observed. [V7 endurance](../../lab/m512/results/v7-endurance.json).

The first longer V7 attempt reached 61 commands before its next output marker
failed near the intentional 15-minute authentication expiry. The service remained
supervised and a fresh authenticated connection worked. The corrected harness
explicitly signs in again and reacquires keyboard ownership; application expiry
was not relaxed. Earlier short harness failures involved a serial-listing timeout,
a wrong UI assertion and a stale-prompt match. Unique returned output markers
replaced prompt-only success tests. Failed records remain private.

BSD passed genuine vi insert/write/redraw/delete/readback and pager/observer
checks across VT100, VT52 and VT220 in Chromium, Firefox and WebKit (nine cases).
RSX passed Chromium VT100 HELLO, HELP and PIP listing. Its initial disposable copy
inherited the immutable base's read-only permissions: original SIMH reported a
read-only disk and startup writes failed. That attempt was stopped and retained;
only the disposable working file was made writable for the successful rerun.
During shutdown, overlapping original startup work delayed dismount; the recorded
SHUTUP timeout was not hidden. The program ultimately reported completion and
executed HALT before simulator exit. This is not an RSX unattended-boot qualification.

A third V7 observer measures actual delivered output and a three-second renderer
stall without sending guest input. Byte rate is sampled workload throughput, not
maximum link capacity. Saturating slow-client/backpressure boundaries remain
separately labeled transport tests. The BSD ten-minute run completed 57 commands, 11 handoffs and four observer
replacements. Sampled bridge RSS was 12,408–14,716 KiB, with 11–14 descriptors
and 14–17 goroutines; whole-container charge was 52,056,064–73,523,200 bytes.
Bridge CPU averaged 0.205% of one core, allocation totaled 65,496,920 bytes over
28 collections, and no cgroup OOM/max event occurred. Echo round trips were
110–124 ms, including emulator polling, relay and browser harness. A separate
V7 observer received 7,259 bytes over 93.506 seconds (about 77.6 B/s) and recovered
read-only after its renderer stall. These are sampled workloads, not capacity
benchmarks. [BSD endurance](../../lab/m512/results/bsd-endurance.json) and
[passive throughput](../../lab/m512/results/passive-throughput.json).

The final executable also passed the original three-phase LP11/PC11 and V7
plot workflow in Chromium, Firefox and WebKit: **20,205 printer bytes**,
**12,288 punch/reader bytes**, verified reader positions and EOF, and byte-exact
completed downloads in WebKit. A further Chromium pass verified byte-exact
retention after the device producer exited. The whole-container budget for this separate two-simulator
phase was explicitly raised to 128 MiB after the 96 MiB endurance run ended;
the installed service’s mandatory 96 MiB boundary was not changed. The device
workflow uses explicit manual guest approvals, distinct from supervised endurance.
[Device records](../../lab/m512/results/devices.json) and
[equipment/browser records](../../lab/m512/results/equipment.json) and
[post-producer retention](../../lab/m512/results/equipment-retained.json).

## E. Sharing and provider boundary

A reproduced delayed HTTP publication could cross another page's revocation and
recreate consent. M5.12 adds a mandatory adapter-instance/revision publication
epoch spanning the app’s adapter-status observation through publication; stale/missing epochs fail
closed. Existing callback-time revocation and receipt checks remain.

The genuine supervised V7 browser supplied a deliberately selected `pwd` excerpt
to the modified pinned Hacker Replicant and real local Gemma 4 12B. Actual expiry,
revocation, cross-page receipt substitution, source disconnect, same-count view
replacement and malformed chat checks passed. Stopping the owned model gateway
returned HTTP 502 without fallback; restarting it allowed a new explicit plain-chat
request. No old excerpt was automatically sent. Isolated route tests cover delayed
model cancellation, request-slot recovery and the publication race. These are
multiple authenticated pages, not an independent multi-tenant security audit.

Text already submitted cannot be recalled. The lab-only guard remains disabled
outside explicit setup. See the [independent-review packet](../security/M5.12-replicant-review.md)
and [genuine sharing summary](../../lab/m512/results/sharing.json).

## F. Historical reference and model qualification

The catalog has 36 source notes and 15 deterministic facts. New notes distinguish
RT-11 multiterminal I/O and RSTS/E generated lines; the RSX password-lifetime note
now includes its separate expired-password flag. No inference engine or guest
permissions were expanded.

Eight natural-language questions and twelve claim cases were frozen before the
qualification run. The checker was not tuned against them. Real Gemma gave seven
of eight requested distinctions and one cautious incomplete MOVB-memory answer.
All eight citation IDs referred to supplied notes, but one answer presented a
project paraphrase as if it were a direct guide quotation. Thus citation-ID validity
is not quotation or source-text validity. No wrong core distinction was found in
this small set; that is not general accuracy or independent historical approval.

The unchanged deterministic checker recognized **2/12** cases, both correctly;
it missed five contradicted statements and left the rest unverified. No false
positive certification occurred in this set. These cases differ from M5.11's
3/18 corpus, so their percentages are not a measured improvement. Source-informed
human review remains necessary. [Raw answers and per-case review](../../lab/m512/results/model-answers.json),
[claim results](../../lab/m512/results/claims.jsonl), and frozen inputs are retained.

## G. ARM64 lifecycle and candidate packaging

A disposable Debian Trixie ARM64 VM had a 1 GiB ceiling and a two-core CPU-time
quota. Its network interface was disabled after prerequisite installation. The
normal compatibility preflight correctly refused absent Oscar launcher/panel
programs; no fake executables were introduced to make it pass. The authorized
lab then separately exercised the package alongside an independently launched
original SIMH/V7 process. This is package lifecycle qualification, not a fresh-card
or complete original-installation replay.

Checks covered inner checksums, stopped/disabled installation, private credentials,
HTTPS, detached startup, explicit approval, real browser commands, disconnect,
restart, SIGKILL, upgrade, actual M5.11 rollback and restoration, and uninstall.
The final runtime also passed supervised browser access. Browser laboratory
contexts explicitly accepted their private self-signed certificates; this is not
public certificate-deployment acceptance. The separate sharing/gateway setup used
its private CA trust configuration. The old binary refused
the new supervision key; rollback succeeded after explicitly restoring the prior
reviewed configuration. The newer supervised configuration was restored before
final verification. Configuration compatibility is an operator step, not an
implicit downgrade of protection.

Memory-controller removal in a disposable test slice caused refusal **before
HTTPS opened**. The restored unit retained `MemoryMax=96M`, `MemorySwapMax=0`,
`NoNewPrivileges`, private devices, protected home, strict filesystem protection
and `Restart=no`. OrbStack's type-wide weakening settings were countered by
reasserting the distributed confinement. No guard was removed to obtain a pass.

Both original console and independent serial V7 access survived companion
transitions and complete managed uninstall. V7 was synced, original SIMH exited,
source/executable/base hashes matched, and private working media/evidence were
exported before deleting the owned VM. [Lifecycle](../../lab/m512/results/arm64-lifecycle.json),
[faults](../../lab/m512/results/arm64-failures.json),
[final browser](../../lab/m512/results/arm64-browser-final.json), and
[cleanup](../../lab/m512/results/arm64-cleanup.json).

VT11 remains a secondary proposal: original SIMH owns display execution and

sequence/reset and nonblocking delivery contract. No functional VT11 browser
claim is made. The RT-11 configuration examined here excludes VT11 support.
See [graphics source findings](../technical/graphics-foundations.md).

Recommend M5.13: independent review of the identity and sharing contracts,
release-matched RT-11 build/diagnostic qualification, an authorized complete RSTS
regeneration kit, and improved held-out historical claim recognition using a
separate development corpus. Production observer deployment and repaired physical
coexistence remain separate, explicitly authorized milestones.
